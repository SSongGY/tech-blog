`D:\workspace\claude\tech_blog`에서 오늘치 글 2편을 작성한다.
[CLAUDE.md](../../CLAUDE.md)의 규칙을 그대로 따른다. 특히 **검증되지 않은 문장은 쓰지 않는다.**

## 절차

1. `python scripts/blog.py status`로 백로그 잔량과 미검증 글을 확인한다.
   - `todo`가 `low_watermark` 이하면 `topics/backlog.yaml`에 주제를 10개 이상 보충한다.
     보충할 때 `topics/published.md`를 먼저 읽어 중복을 피하고, 각 주제에 `angle`을 반드시 채운다.
   - 이전 날짜의 `verified: false` 글이 남아 있으면 그것부터 마무리한다.

2. `python scripts/blog.py pick`으로 주제 2개를 받는다.
   - **이 환경에서 예제를 실행할 수 없는 주제는 건너뛴다.** 필요한 런타임·DB·유료 서비스가 없으면
     해당 주제는 `todo`로 두고 `pick -n 4`로 더 받아 실행 가능한 것을 고른다.
     건너뛴 이유를 커밋 메시지에 한 줄 남긴다.

3. 각 주제마다:
   - `python scripts/blog.py new <id> <영문-slug>`로 폴더를 만든다
   - `references/naming-conventions.md`에서 해당 언어의 명명 규칙을 확인한다
   - `code/`에 **그 자체로 실행되는** 예제를 작성한다. 난수는 시드를 고정한다
   - **예제를 실제로 실행한다.** 출력이 기대와 다르면 글이 아니라 이해를 고친다
   - 실행 결과를 본문에 그대로 싣는다. 측정값·실행계획·에러 메시지를 지어내지 않는다
   - 본문에 사실 주장을 썼으면 그 주장도 따로 검증한다
     (예: "통계가 없으면 스킵 스캔이 안 나온다" → `ANALYZE` 유무로 직접 돌려 확인)
   - 예상과 달랐던 결과가 나오면 **그것을 글의 중심에 놓는다.** 가장 값이 나가는 부분이다
   - `code/README.md`에 실행 방법과 바꿔볼 값을 적는다
   - Mermaid 도식을 최소 1개 넣는다
   - 본문 길이를 1,800~3,500자(공백·코드블록·표 제외)로 맞춘다
   - 검증이 끝나면 프론트매터를 `verified: true`로 바꾼다

4. `python scripts/blog.py done <id>`로 두 주제를 완료 처리한다.

5. 커밋한다. 글 2편을 **각각 별도 커밋**으로 나눈다.
   ```
   post: <제목>

   - 카테고리/난이도
   - 예제: <파일> (<언어>, 실행 검증 완료)
   - 측정 결과 요약 한두 줄
   ```
   원격이 설정돼 있으면 push한다.

6. 마지막에 다음을 보고한다.
   - 쓴 글 2편의 제목과 한 줄 요약
   - 각 글에서 **예상과 달랐던 결과**
   - 건너뛴 주제가 있으면 그 이유
   - `python scripts/blog.py status` 결과

## 티스토리 발행

발행은 수동이다. 티스토리·네이버 모두 글쓰기 API가 종료되어 자동 발행이 불가능하다.
`python scripts/blog.py tistory <slug>`로 변환본과 발행 정보를 뽑아 사용자에게 안내한다.
Mermaid 도식은 티스토리에서 렌더링되지 않으므로 이미지로 바꿔야 한다는 점을 함께 알린다.

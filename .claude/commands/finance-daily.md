주식·재무 공부 글 2편을 쓴다. 기술 트랙과 **별도 트랙**이고 자리를 나눠 쓰지 않는다.
규칙은 [CLAUDE.md](../../CLAUDE.md) **§13 주식·재무 글**이 본체다.

**타협 불가**: 숫자는 가상 회사로 만든다 · 특정 종목을 사라·팔라로 읽힐 문장을
쓰지 않는다 · 계산이 들어가면 직접 계산해 출력을 남긴다.

## 명령을 실행하는 방법 — 이 절을 먼저 읽는다

무인 회차가 권한 프롬프트 앞에서 멈추지 않으려면 아래를 지킨다. 허용 규칙이
`Bash(...)` 형태로 붙어 있고, 명령의 **맨 앞부분**으로만 맞춰 보기 때문이다.

- **Bash 도구로 실행한다.** PowerShell 도구로 같은 일을 하면 규칙이 달라 전부 물어본다
- **`cd`로 작업 폴더를 옮기지 않는다.** 이미 저장소 루트에서 시작한다
- **명령 앞에 아무것도 붙이지 않는다.** 환경변수도, 변수 할당도
- **`python -c`로 즉석 코드를 짜지 않는다.** 자주 하는 일은 `blog.py`에 명령이 있다
- **복합 명령을 피한다.** `for`·`while` 루프, `sleep` 대기, `find -exec`,
  서브셸, `xargs`, 명령 치환 `$(...)`
- **`rm`·`mv`를 쓰지 않는다.** 버릴 파일은 이름을 `probe`로 시작하면 gitignore된다

## 시작 전 — 다른 회차와 겹치지 않는지 확인

`mcp__scheduled-tasks__list_task_runs`로 `tech-blog-daily`·`tech-blog-exam`·
`tech-blog-concept`에 `status: running`인 실행이 있는지 본다.

**먼저 그 회차가 살아 있는지 본다.** `started_at`이 **3시간**을 넘었으면 돌고 있는
것이 아니라 **멈춘 것이다.** 정상 회차는 길어야 한 시간 남짓이다. 멈춘 것으로
판단되면 기다리지 말고 `PushNotification`으로 알리고 오늘 회차는 건너뛴다.
저장소는 건드리지 않는다.

3시간이 안 됐으면 `list_task_runs`를 다시 불러 확인한다. 세 번 봐도 안 끝나면
오늘은 건너뛰고 보고한다.

## 1. 주제 고르기

```bash
python scripts/blog.py pick-finance
```

**백로그 순서가 곧 학습 순서다.** 재무제표 세 장 → 비율 → 밸류에이션 순으로
쌓이게 짜 두었다. 앞질러 고르지 않는다.

## 2. 조사

- **회계 기준은 1차 자료를 쓴다.** K-IFRS 기준서, 금융감독원 회계포털,
  한국거래소 규정. 용어 정의가 기준서에 있으면 그것을 쓴다
- 제도·규정에는 **발효일**을 적는다. 공시 시한과 거래 제도는 바뀐다
- 비율의 "적정 수준"을 쓸 때는 **그 기준의 출처를 밝힌다.** 근거 없이
  "부채비율 200% 이하가 건전하다"고 쓰지 않는다

## 3. 폴더 만들기

```bash
python scripts/blog.py new fin-001 balance-sheet-basics
```

`posts/Finance/<분야>/<날짜>-<slug>/`에 만들어진다.

## 4. 예제 — 가상 회사로 계산한다

**실제 기업의 재무제표를 쓰지 않는다.** 숫자가 분기마다 바뀌어 글이 조용히 낡고,
특정 종목을 들면 계산 설명이 투자 권유로 읽힌다. 회사 이름은 `가나전자`처럼
실재하지 않는 것을 쓴다.

계산이 들어가면 `code/`에 파이썬으로 두고 돌린다.

```bash
python scripts/blog.py run-example posts/Finance/<분야>/<날짜>-<slug>/
```

**보이고 싶은 대비를 숫자로 설계한다.** 부채만 다른 두 회사, 이익은 같은데
현금흐름이 갈리는 두 회사처럼. 이게 가상 회사를 쓰는 진짜 이유다.

용어 정의만 다루는 글은 계산이 없으므로 `manual-only`로 쓰고 본문에 밝힌다.

## 5. 도식

§4를 그대로 따른다. 재무제표 세 장이 이어지는 경로, 현금흐름 세 갈래의 부호 조합
같은 것은 그림 없이 설명되지 않는다. 출처 줄(`> **출처**:`)을 빠뜨리지 않는다.

## 6. 마무리

```bash
python scripts/blog.py lint
python scripts/blog.py index
python scripts/blog.py done fin-001
```

`lint`가 `[OK]`가 아니면 고치고 다시 돌린다.

두 시간 전 기출 회차가 푼 문제의 **개념**을 정리한다. 답안(`exam` 트랙)이 아니라
**개념 글(`pe` 트랙)** 2편이다. 둘의 차이는 `CLAUDE.md` §11에 있다.


## 명령을 실행하는 방법 — 이 절을 먼저 읽는다

무인 회차가 권한 프롬프트 앞에서 멈추지 않으려면 아래를 지킨다. 허용 규칙이
`Bash(...)` 형태로 붙어 있고, 명령의 **맨 앞부분**으로만 맞춰 보기 때문이다.

- **Bash 도구로 실행한다.** PowerShell 도구로 같은 일을 하면 규칙이 달라 전부 물어본다
- **`cd`로 작업 폴더를 옮기지 않는다.** 이미 저장소 루트에서 시작한다.
  다른 경로의 파일은 절대경로로 읽는다
- **명령 앞에 아무것도 붙이지 않는다.** 환경변수(`PYTHONUTF8=1`)도, 변수 할당(`$x=...`)도.
  앞에 한 토막이 붙으면 규칙이 안 맞는다. `blog.py`는 인코딩을 스스로 맞춘다
- **`python -c`로 즉석 코드를 짜지 않는다.** 임의 코드는 규칙으로 허용할 수 없는 종류다.
  자주 하는 일은 `blog.py`에 명령이 있다 (`env`·`recent`·`check-svg`·`check-links`·`pdf-text`).
  없으면 그때 `blog.py`에 명령을 추가하고, 그 사실을 보고에 적는다
- **파일 내용은 Edit 도구로 고친다.** `sed -i`·`[IO.File]::WriteAllText`·
  `Set-Content`·`>` 리다이렉션은 Write·Edit 의 경로 제한을 우회하므로 쓰지 않는다
- **heredoc 뒤에 `&&`·`;` 를 붙이지 않는다.** `git commit -F - <<'MSG' && git push`
  처럼 쓰면 heredoc 본문이 두 번째 토막에 섞여 들어가 규칙과 안 맞는다.
  커밋과 푸시는 따로 부른다
- **공유 파일은 골라 담지 않는다.** `POSTS.md`·`topics/backlog.yaml`·
  `topics/published.md` 에 다른 회차의 수정이 섞여 올라가도 괜찮다 — 전부
  사실인 기록이다. 패치 파일을 만들어 `git apply` 하거나 줄 단위로 고르지
  않는다. 위험한 것은 **추적되지 않은 새 폴더**뿐이고 그건 `git add -u` 가 막는다
- **백로그와 발행 이력은 손으로 고치지 않는다.** `blog.py done`·`exam-done` 이
  두 파일을 같이 고친다
- **복합 명령을 피한다.** `for`·`while` 루프, `sleep`으로 버티는 대기,
  `find -exec`, 서브셸 `( ... &)`, `xargs`, 명령 치환 `$(...)`은
  규칙으로 맞출 수 없다
- 웹 요청은 `curl` 대신 `WebFetch`·`WebSearch`를 쓴다.
  받은 것이 PDF면 `python scripts/blog.py pdf-text <경로> --find <검색어>`로 본문을 본다


## 먼저 읽을 것

1. `CLAUDE.md` **§7 정보관리기술사 글** — 개념 글의 9단 구조. 이게 본체다
2. `CLAUDE.md` **§10 1차 자료가 없는 최신 주제** — 출처 등급
3. `CLAUDE.md` **§4 도식 규칙** — SVG 작성과 출처 표기

## 시작 전 — 다른 회차와 겹치지 않는지 확인

`mcp__scheduled-tasks__list_task_runs`로 `tech-blog-exam`과 `tech-blog-daily`에
`status: running`인 실행이 있는지 본다. 같은 저장소에 두 세션이 동시에 쓰면
커밋이 엉킨다.

**먼저 그 회차가 살아 있는지 본다.** `started_at`이 **3시간**을 넘었으면
돌고 있는 것이 아니라 **멈춘 것이다.** 정상 회차는 길어야 한 시간 남짓이다.
`last_activity_at`이 방금이어도 마찬가지다 — 그 값은 세션에 무엇이 닿을
때마다 갱신돼서 살아 있는 것처럼 보인다.

멈춘 것으로 판단되면 **기다리지 않는다.** `PushNotification`으로 알리되,
터미널이 켜져 있으면 전송되지 않으므로 **보고 맨 앞에도 같은 내용을 적는다.**
어느 작업이 언제부터 멈췄는지 한 줄이면 된다.

**그리고 오늘 회차를 건너뛰지 않는다.** 멈춘 회차가 있어도 쓸 것은 쓴다.
`git add -A` 를 쓰지 않으므로 그 세션이 쓰다 만 폴더가 내 커밋에 섞이지
않는다 (아래 커밋 절을 그대로 따른다). 예전에는 건너뛰었는데, 멈춘 회차
하나 때문에 나머지 루틴이 전부 멈춰 닷새가 빈 적이 있다.

다만 **그 회차가 쓰던 글은 건드리지 않는다.** 같은 주제가 잡히면
`pick` 이 걸러 주므로 그냥 다음 주제로 간다.

**알리지 않고 조용히 건너뛰지 않는다.** 2026-09-23 에 작성 회차가 멈춘 뒤
기출·개념이 닷새 동안 매번 건너뛰었는데, 그 보고가 각자의 세션 안에만 있어서
아무도 보지 못했다.

3시간이 안 됐으면 **셸로 기다리지 않는다.** `while`과 `sleep`으로 커밋을
기다리는 루프는 허용 규칙으로 맞출 수 없어 회차가 그 자리에서 멈춘다.
`list_task_runs`를 다시 불러 확인한다 — 도구 호출은 권한 규칙과 무관하다.

세 번 확인해도 안 끝나면 오늘은 건너뛰고 **그 사실을 보고한다.** 억지로 같이 쓰지 않는다.

## 1. 주제 고르기

```bash
python scripts/blog.py pick-concepts
```

**기출발**로 표시된 주제를 먼저 준다 — 직전 기출 회차의 답안에서 등록된 개념이다.
기출발이 2개가 안 되면 기존 `pe` 백로그에서 채워 준다. 그것도 정상이다.
손으로 고르지 않는다.

## 2. 글 만들기

```bash
python scripts/blog.py new <topic_id> <slug>
```

§7의 구조를 그대로 따른다.

1. 들어가며 — 왜 시험에 나오는지, 실무에서 어떤 문제를 푸는지 (3~4문장)
2. 정의 — **한 문장으로 끊어지는** 정의. 답안 첫 줄에 그대로 쓸 수 있어야 한다
3. 등장 배경 — 이전 방식의 무엇이 문제였는지
4. 구성요소 / 절차 — **개수를 반드시 명시한다** ("4단계", "6가지")
5. 도식 — 답안지에 5분 안에 옮겨 그릴 수 있어야 한다
6. 비교 — 유사 개념과의 대비 표
7. 적용 시 고려사항 — 최소 3개
8. 정리 — 두문자나 개수로 묶은 암기 단서
9. 참고 자료

분량은 1,500~3,000자. `manual-only`가 기본이고 본문에 **"실행 검증 없음"**을 밝힌다.
계산 문제(스케줄링, 페이지 교체, 정규화)는 직접 검산해 `executed`로 올린다.

## 3. 답안 글과 서로 잇는다

같은 주제의 기출 답안이 있으면 **양쪽에 링크를 넣는다.** 한쪽만 걸면 쓸모가 없다.

```bash
ls posts/PE/exam/
```

개념 글 **참고 자료 앞**에:

```markdown
> 기출 답안: [기출문제 — 제목](../exam/2026-09-21-<slug>/index.md)
```

답안 글의 `끝` **위**에:

```markdown
> 개념 정리: [제목](../<분야>/2026-09-21-<slug>/index.md)
```

답안 파일을 고쳤으면 그것도 같이 커밋한다.

## 4. 검사

```bash
python scripts/blog.py lint
```

`[NG]`가 하나라도 있으면 고친 뒤 다시 돌린다.

## 5. 마무리

```bash
python scripts/blog.py done <topic_id>
python scripts/blog.py index
# 이번 회차가 만든 폴더만 이름을 대고, 나머지는 추적 중인 파일의 수정만 집는다.
# git add -A 를 쓰면 다른 회차가 쓰다 만 폴더까지 올라간다.
git add posts/<카테고리>/<...>/
git add -u
git commit -F - <<'MSG'
post: <제목>

{본문 — 무엇을 왜 바꿨는지}

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
MSG
git push
```

끝나면 무엇을 썼는지, 기출발이었는지 백로그였는지 한두 줄로 보고한다.

## 하지 말 것

- **답안 형식(`Ⅰ.` `가.` `①`, 마지막 `끝`)으로 쓰지 않는다.** 그건 `exam` 트랙이다.
  여기는 개념 글이므로 §7의 9단 구조와 평서체 본문으로 쓴다
- 출처 없는 정의 금지, 항목 개수 누락 금지, 근거 없는 수치 금지
- 2편을 채우려고 기준을 낮추지 않는다. 못 쓰겠으면 1편만 쓰고 이유를 보고한다
- 다른 루틴이 돌고 있으면 저장소를 건드리지 않는다

두 시간 전 기출 회차가 푼 문제의 개념을 정보관리기술사 개념 글 2편으로 정리하고 커밋한다.

## 작업 위치

`D:\workspace\claude\tech_blog` (git 저장소, origin은 https://github.com/SSongGY/tech-blog, 공개)

## 먼저 읽을 것 — 반드시 이 순서로

1. `CLAUDE.md` — 특히 **§7 정보관리기술사 글**(개념 글의 9단 구조), **§10 출처 등급**, **§4 도식 규칙**
2. `.claude/commands/concept-daily.md` — 오늘 수행할 절차서. **이 문서의 단계를 그대로 따른다**

읽은 뒤 `concept-daily.md`의 단계를 순서대로 수행한다.

## 시작 전 — 다른 회차와 겹치지 않는지 확인

`mcp__scheduled-tasks__list_task_runs`를 `tech-blog-exam`과 `tech-blog-daily`로 각각 호출해
`status: running`인 실행이 있는지 본다. 돌고 있으면 **저장소를 절대 건드리지 않는다.**
끝날 때까지 기다리거나, 오래 걸릴 것 같으면 오늘은 건너뛰고 그 사실을 보고한다.
같은 저장소에 두 세션이 동시에 쓰면 커밋이 엉킨다.

## 무엇을 쓰는가

`python scripts/blog.py pick-concepts`가 정해준다.
15시 답안에서 `--origin exam`으로 등록된 **기출발** 주제를 먼저 준다.
기출발이 2개가 안 되면 기존 `pe` 백로그에서 채워 준다 — 그것도 정상이다.
손으로 고르지 않고, 편수를 늘리지도 않는다.

## 이 루틴이 쓰는 것은 답안이 아니라 개념 글이다

`Ⅰ.` `가.` `①` 같은 답안 형식으로 쓰지 않는다. 마지막에 `끝`도 쓰지 않는다.
그것은 15시 `exam` 트랙이 하는 일이다. 여기는 §7의 9단 구조와 평서체 본문으로 쓴다.

## 절대 지킬 것

- **정의는 출처 있는 것을 쓴다.** ISO/IEEE 표준, 공식 가이드, 원 논문 순
- **항목 개수를 반드시 명시한다** ("4단계", "6가지"). 답안에서 개수가 곧 점수다
- **근거 없는 수치 금지.** 성능 수치·시장 통계는 원 출처가 1차일 때만
- 1차 자료가 없는 최신 주제는 건너뛰지 말고 **2차 자료 3건 교차 확인**으로 쓰되 밝힌다 (§10)
- 같은 주제의 기출 답안이 `posts/PE/exam/`에 있으면 **양쪽에 서로 링크를 넣는다**
- 회사 내부 정보 금지 (CLAUDE.md §6)
- **2편을 채우려고 기준을 낮추지 않는다.** 못 쓰겠으면 1편만 쓰고 이유를 보고한다

## 마무리

`lint`가 전부 `[OK]`가 된 뒤에 `done` → `index` → 커밋 → 푸시한다.
끝나면 무엇을 썼는지, 기출발이었는지 백로그였는지 한두 줄로 보고한다.

커밋 메시지 마지막 줄은 **이 형태 그대로** 쓴다. 자기 모델 이름을 적지 않는다.

## 명령 실행 규칙

- **Bash 도구로 실행한다.** PowerShell 도구는 허용 규칙이 없어 전부 물어본다
- **`cd`로 작업 폴더를 옮기지 않는다.** 이미 저장소 루트에서 시작한다
- **명령 앞에 환경변수나 변수 할당을 붙이지 않는다.** 규칙이 맨 앞부분으로 맞춰 본다
- **`python -c`로 즉석 코드를 짜지 않는다.** 필요한 일은 `blog.py`에 명령이 있다.
  PDF 본문은 `python scripts/blog.py pdf-text <경로> --find <검색어>`
- `for`·`while` 루프, `sleep` 대기, `find -exec`, 서브셸, `xargs`,
  명령 치환 `$(...)` 을 쓰지 않는다. 다른 회차를 기다려야 하면
  `mcp__scheduled-tasks__list_task_runs` 를 다시 부른다

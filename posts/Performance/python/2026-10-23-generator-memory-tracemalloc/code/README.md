# 제너레이터가 실제로 아끼는 것 — tracemalloc 으로 본 메모리

같은 처리를 리스트로 전부 담을 때와 제너레이터로 흘릴 때의 **최대 메모리**를
`tracemalloc` 으로 재고, 두 번 훑어야 하는 작업에서는 어느 쪽이 손해인지까지 본다.

의존성은 없다. 표준 라이브러리의 `tracemalloc`, `itertools`, `time` 만 쓴다.

## 실행

```bash
python generator_memory.py
```

## 바꿔 볼 값

- `RECORD_COUNT` — 레코드 수. 리스트 쪽 최대 메모리는 여기에 비례해 늘고
  제너레이터 쪽은 거의 그대로다. 둘의 비율이 어떻게 벌어지는지 본다
- `make_records` 의 dict 키 개수 — 한 레코드가 커질수록 격차가 커진다
- 4절의 `islice(errors, 5)` 의 5 — 앞부분을 더 많이 가져갈수록 두 방식의 차이가 줄어든다

## 주의

`tracemalloc` 은 **파이썬이 잡은 메모리만** 센다. 인터프리터 자체나 C 확장이
직접 잡은 메모리는 빠지므로, 프로세스의 RSS 와 같은 값이 아니다.
시간은 환경에 따라 흔들린다. 구조적 결과(최대 메모리의 자릿수 차이, 결과 일치 여부)만
본문의 주장과 맞으면 된다.

# 예제 코드 — 문자열을 더하는 네 가지 방법의 비용

같은 조각 N개를 `+=`, `StringBuilder`, `String.join`, `Stream` 으로 이어 붙여 시간과 할당량을 잰다. 마지막에 `javap -c` 로 `+` 가 어떤 바이트코드가 되는지 본다.

| 파일 | 하는 일 |
|---|---|
| `StringConcatCost.java` | 네 방법을 같은 입력으로 돌리고 시간·할당량을 찍는다 |
| `run.sh` | 컴파일 → 실행 → `javap` |

`javac`/`java`/`javap`(JDK 8)이 PATH에 있어야 한다. 다른 의존성은 없다.

## 실행

```bash
bash run.sh
```

컴파일 결과는 `probe_classes/` 로 떨어진다. `probe` 로 시작하므로 저장소가 추적하지 않는다.

## 바꿔볼 값

| 자리 | 기본값 | 바꾸면 |
|---|---|---|
| `PIECE_COUNTS` | 1000, 10000, 30000 | 키울수록 `+=` 의 시간과 할당량이 제곱으로 늘어난다 |
| `ROUNDS` | 5 | 가장 빠른 회차를 쓰므로 늘려도 값이 크게 바뀌지는 않는다 |
| `makePieces` 의 조각 길이 | 6자 | 길수록 `+=` 가 복사하는 양이 늘어난다 |

시간은 PC 상태에 따라 흔들린다. 할당량(KB)은 거의 같아야 한다.

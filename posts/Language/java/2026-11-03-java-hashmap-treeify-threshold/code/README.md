# 예제 코드 — HashMap 버킷이 트리로 바뀌는 순간

`hashCode()` 가 항상 같은 키를 한 버킷에 몰아넣고, 버킷의 노드가 `Node` 에서
`TreeNode` 로 바뀌는 시점과 그 전후의 조회 시간을 잰다.

| 파일 | 하는 일 |
|---|---|
| `HashMapTreeify.java` | 충돌 키를 만들고, 리플렉션으로 버킷 노드 종류를 읽고, 조회 시간을 잰다 |
| `run.sh` | 컴파일 → 실행 |

`javac`/`java`(JDK 8)가 PATH에 있어야 한다. 다른 의존성은 없다.

## 실행

```bash
bash run.sh
```

컴파일 결과는 `probe_classes/` 로 떨어진다. `probe` 로 시작하므로 저장소가 추적하지 않는다.

## 바꿔볼 값

| 자리 | 기본값 | 바꾸면 |
|---|---|---|
| `new HashMap<>(64)` 의 초기 용량 | 64 | 63 이하로 주면 §2 도 §1 처럼 리사이즈만 반복한다 |
| `PlainKey.hashCode()` 의 반환값 | 1 | 값을 바꿔도 결과는 같다. `bucketNodeType` 의 버킷 계산만 맞춰 준다 |
| §3 의 키 수 목록 | 8 ~ 16384 | 키가 많을수록 비교 불가 키와 Comparable 키의 차이가 벌어진다. 비교 불가 키는 키 수의 제곱으로 느려지므로 32768 이상은 몇 분이 걸린다 |
| `LOOKUP_ROUNDS` | 10 | 가장 빠른 회차를 쓰므로 늘려도 값이 크게 바뀌지는 않는다 |

시간 측정값은 PC 상태에 따라 흔들린다. 노드 종류와 `table.length` 는 같아야 한다.

## 다른 자바 버전

`HashMap.table` 을 리플렉션으로 여는 부분은 Java 9 이상에서 모듈 시스템에 막힌다.
`--add-opens java.base/java.util=ALL-UNNAMED` 를 `java` 명령에 붙이면 돈다.
트리화 임계값(8 · 6 · 64)은 Java 8 부터 21 까지 같다.

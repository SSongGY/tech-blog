# 금액을 float 으로 더하면 얼마나 틀어지는가

같은 금액 10만 건을 float · Decimal · 정수(전 단위) 세 방식으로 더해 오차와
비용을 재고, 반올림 방식이 합계를 얼마나 가르는지 확인한다.

## 실행

```bash
python money_accumulation.py
```

표준 라이브러리만 쓴다. 난수는 시드를 고정했으므로 같은 입력이 나온다.

## 바꿔 볼 값

- `ITEM_COUNT` 를 `1_000` 으로 줄이면 float 오차가 보이지 않는다. 건수를 올려
  가며 오차가 어느 규모부터 드러나는지 본다.
- `SEED` 를 바꾸면 금액 목록이 통째로 바뀐다. 오차의 크기와 부호가 입력에
  따라 달라지는 것 — 즉 예측할 수 없다는 것 — 을 확인한다.
- 4번 절의 `sample` 목록에 `"1.005"` 같은 값을 추가하면, 십진으로는 딱 절반인데
  2진수로는 절반이 아닌 값이 어떻게 처리되는지 볼 수 있다.

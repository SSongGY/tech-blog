# 인코딩·디코딩이 어긋나는 세 경로

같은 한글을 여러 코덱으로 인코딩해 바이트 수를 대조하고, 잘못된 짝으로 디코딩했을 때
나오는 글자를 재현한다. 각 경우에 **원문을 되돌릴 수 있는지**까지 함께 찍는다.
추가 의존성이 없다. 파이썬 표준 라이브러리만 쓴다.

## 실행

```bash
python mojibake_paths.py
```

## 파일

| 파일 | 무엇 |
|---|---|
| `mojibake_paths.py` | 본문에 실린 세 경로를 순서대로 재현한다 |
| `output.txt` | 실제 실행 기록 (`blog.py run-example` 이 만든다) |

## 바꿔 볼 값

- 0번 절의 `"똠"` 을 다른 글자로 바꿔 본다. EUC-KR 완성형에 없는 한글은 바이트 수가
  갑자기 늘어난다. 완성형에 있는 글자(`"한"`)와 대조하면 차이가 보인다.
- 경로 1의 코덱 목록에 `"cp1252"` 나 `"shift_jis"` 를 넣으면 다른 모양의 깨짐이 나온다.
  깨진 모양만 보고 원래 코덱을 맞히기 어렵다는 것이 이 절의 요점이다.
- 경로 2의 `errors` 목록 순서를 바꿔도 결과는 같다. 중요한 것은 `ignore` 와 `replace` 가
  **되돌릴 수 없는 쪽**이고 `surrogateescape` 만 왕복이 된다는 점이다.

# 예제 코드 — 멱등키로 중복 결제 막기

결제 API 서버 구현 세 가지(`naive`, `check_then_act`, `claim_first`)를 같은 장애 상황 네 가지에 넣고,
외부 결제사가 실제로 승인한 건수를 센다. 멱등키 저장소는 임시 폴더의 SQLite 파일이고,
외부 결제사는 파이썬 객체로 흉내 냈다. 외부 의존성 없이 표준 라이브러리만 쓴다.

## 실행

```bash
python idempotency_key.py
```

## 바꿔볼 값

- `LEASE_TICKS`를 50으로 올리면 D 상황의 t=40 재시도도 409를 받는다. 선점 유효 시간이 복구 시점을 정한다.
- `scenario_c`에서 `server.gateway.hold_first = True` 줄을 지우면 첫 요청이 결제사에서 바로 돌아와,
  두 번째 요청이 오기 전에 끝나 버린다. 그러면 두 구현 모두 저장된 응답을 돌려준다.
  이 줄은 "결제사 응답이 느린 동안 같은 요청이 또 온다"를 매번 재현하려고 넣었다.

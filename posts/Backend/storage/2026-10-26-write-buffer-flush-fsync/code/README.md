# write 는 디스크에 쓰는 것이 아니다

`write` / `flush` / `fsync` 가 각각 어디까지 보장하는지를 시간과 생존 여부로 가른다.
파이썬 표준 라이브러리만 쓰므로 따로 설치할 것이 없다.

## 실행

```bash
python write_durability.py
```

`crash_child.py` 는 본체가 자식 프로세스로 띄운다. 직접 부르지 않아도 된다.

## 무엇을 보여주는가

| 절 | 확인하는 것 |
|---|---|
| 1 | `write` 직후에는 다른 핸들로 아무것도 안 읽힌다. 버퍼가 차면 저절로 넘어간다 |
| 2 | 같은 10,000줄을 네 가지 방식으로 쓰며 걸린 시간 |
| 3 | `os._exit` 로 즉사한 프로세스에서 `flush` 한 줄만 살아남는다 |
| 4 | `fsync` 를 몇 줄마다 부르느냐에 따라 달라지는 시간 |

전원이 끊기는 상황은 여기서 재현하지 않는다. `fsync` 의 보장 범위는 문서 근거로만 쓴다.

## 바꿔볼 값

- `LINES` 를 줄이면 전체가 빨리 끝난다. 줄마다 `fsync` 하는 2절이 가장 오래 걸린다.
- `PAYLOAD` 를 길게 만들면 1절에서 버퍼가 넘어가는 지점이 앞당겨진다.
- `crash_child.py` 의 `os._exit(1)` 을 `sys.exit(1)` 로 바꾸면 파이썬이 파일을 정리하므로
  3절의 `flush 없이` 쪽도 전부 살아남는다.

# 예제 코드 — 캐시 스탬피드를 막는 세 가지 방법 비교

같은 요청열(2분, 초당 50건)을 네 방식에 그대로 먹여 **원본 재계산 횟수**,
**스탬피드 크기**, **대기 요청 수와 평균 대기**, **낡은 값 제공 수**를 잰다.
시간은 가상 시계로 돌리는 이산 사건 모의라 스레드 경합에 흔들리지 않는다.

## 실행

```bash
python stampede.py
```

의존성 없음. 난수 시드를 고정했으므로 몇 번을 돌려도 같은 표가 나온다.

## 바꿔 볼 값

| 값 | 보이는 것 |
|---|---|
| `MEAN_INTERVAL_MS` | 요청이 몰릴수록 "아무 대책 없음"의 최대 동시가 어떻게 커지는지 |
| `RECOMPUTE_MS` | 재계산이 길수록 뮤텍스 락의 평균 대기가 어떻게 늘어나는지 |
| `BETA` | β 를 키우면 조기 재계산이 더 빨라져 재계산 횟수가 느는 것 |
| `TTL_MS` | TTL 을 줄이면 전 방식의 재계산 횟수가 같이 느는 것 |

# 처리율 제한 비교

고정 창·슬라이딩 로그·슬라이딩 카운터·토큰 버킷·누출 버킷을 같은 요청열에 돌려
허용 건수와 "어느 10초 구간에든 통과한 최대 건수"를 잰다. 실제 시계 대신 정수 밀리초 요청열을
넣으므로 몇 번을 돌려도 결과가 같다. 표준 라이브러리만 쓴다.

## 실행

```bash
python rate_limiters.py
```

## 바꿔 볼 값

- `LIMIT`·`WINDOW_MS` — 한도를 바꾸면 경계 실험의 "두 배 통과"가 한도에 비례해 커진다.
- `TokenBucket.capacity` — 버킷 크기를 한도보다 작게(예: 3) 잡으면 순간 몰림이 줄고, 평균 처리율은 그대로다.
- `scenario_random()`의 `expovariate(1.5)` — 평균 도착률을 한도(초당 1건) 근처로 내리면
  슬라이딩 카운터 근사의 오차가 어떻게 달라지는지 본다.

# 예제 코드 — 서킷 브레이커의 세 상태

가짜 시계 위에서 초당 10건의 요청을 하류 서비스로 보내며, 서킷 브레이커의 Closed·Open·Half-Open이
각각 어떤 장애를 막는지 확인한다. 도착과 완료를 시간순 이벤트로 처리하므로 타임아웃으로 끝나는 호출의 결과가
늦게 들어오는 것까지 반영된다. 난수를 쓰지 않아 몇 번을 돌려도 같은 결과가 나온다. 표준 라이브러리만 쓴다.

## 실행

```bash
python circuit_breaker.py
```

## 바꿔볼 값

- `CircuitBreaker(5, window=10.0, …)`의 첫 인자(실패 임계)를 2로 낮추면 1-1도 열린다. 간헐 오류의 빈도와 창 크기의 관계를 본다.
- `TIMEOUT`을 0.5로 줄이면 2-1의 동시 진행 최대가 줄어든다. 타임아웃이 짧을수록 브레이커가 열리기 전 쌓이는 호출도 줄어든다.
- `trial_limit`을 10으로 올리면 Half-Open이 회복 중인 서비스에 시험 호출을 한꺼번에 보내 3-1에 가까워진다.

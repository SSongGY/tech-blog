======================================================================
[API·서비스 모두 1000ms, 재시도 2회 × 3회]
  설정  API 타임아웃 1000ms · 재시도 API 2회 × 서비스 3회 · DB 응답 5000ms
  클라이언트    1004ms — 기다리다 끊었다 (서버 응답 없음)
  서버 작업     6065ms 에 끝났다
  버려진 일     5061ms
  DB 호출     6회

[같은 설정에서 재시도를 서비스 한 곳으로 모으면]
  설정  API 타임아웃 1000ms · 재시도 API 1회 × 서비스 3회 · DB 응답 5000ms
  클라이언트    1014ms — 기다리다 끊었다 (서버 응답 없음)
  서버 작업     3045ms 에 끝났다
  버려진 일     2031ms
  DB 호출     3회

======================================================================
4. 데드라인을 넘기고, 한 번 시도의 예산은 고정하는 경우
======================================================================
  재시도 횟수로 예산을 미리 나누지 않는다. 한 번 시도에 주는 시간은
  평소 걸리는 400ms 에 여유를 더한 500ms 로 고정하고,
  그만큼이 남아 있을 때만 다시 시도한다.

[의존성이 막혔을 때]
  설정  예산 970ms · 한 번 시도 500ms · DB 응답 5000ms
  클라이언트     971ms — 서버가 돌려준 실패 응답을 받았다
  서버 작업      971ms 에 끝났다
  버려진 일        0ms
  DB 호출     2회

[의존성이 멀쩡할 때 (400ms 면 답이 온다)]
  설정  예산 970ms · 한 번 시도 500ms · DB 응답 400ms
  클라이언트     442ms — 성공 응답을 받았다
  서버 작업      442ms 에 끝났다
  버려진 일        0ms
  DB 호출     1회

[첫 호출만 막히고 다음부터 정상일 때]
  설정  예산 970ms · 한 번 시도 500ms · DB 응답 [5000, 400]ms
  클라이언트     942ms — 성공 응답을 받았다
  서버 작업      942ms 에 끝났다
  버려진 일        0ms
  DB 호출     2회

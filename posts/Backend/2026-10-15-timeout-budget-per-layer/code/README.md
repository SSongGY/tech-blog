# 예제 코드 — 타임아웃을 계층마다 다르게 줘야 하는 이유

API → 서비스 → DB 세 계층을 스레드로 흉내 내고, 타임아웃을 (a) 계층마다 같은
값으로 주었을 때와 (b) 예산을 쪼개 내려보냈을 때의 차이를 잰다.

재는 값은 넷이다 — DB 호출 횟수, 클라이언트가 손을 뗀 시각, 서버 작업이
끝난 시각, 그리고 그 둘의 차이(버려진 일).

## 실행

```bash
python timeout_budget.py
```

의존성은 없다. 표준 라이브러리만 쓴다. 전체가 25초쯤 걸린다 — 막힌 의존성을
흉내 내느라 실제로 그만큼 기다리기 때문이다.

## 바꿔볼 값

- `DB_STALL_MS` — 막힌 의존성의 응답 시간. 키울수록 버려진 일이 비례해 늘어난다
- `API_RETRIES` × `SERVICE_RETRIES` — DB 호출 횟수가 이 둘의 곱이 되는 것을 본다
- `DB_HEALTHY_MS` — 400ms보다 키우면, 예산을 쪼갠 쪽에서 멀쩡한 의존성까지
  실패로 떨어지는 지점을 찾을 수 있다
- `SAFETY_MARGIN_MS` — 0으로 두면 서버가 응답을 돌려보내기 전에 클라이언트가
  먼저 끊는다

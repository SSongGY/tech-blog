# 커넥션 풀 크기 측정 — 예제

파이썬 표준 라이브러리만 쓴다. 설치할 것이 없다. 측정에 10~20초쯤 걸린다.

## 실행

```bash
python pool_sizing.py
```

## 무엇을 재는가

백엔드가 **동시에 4건까지만** 처리하도록 세마포어로 막아 두고, 커넥션 풀 크기만
1부터 64까지 바꿔 가며 같은 300건을 처리시킨다. DB 서버의 CPU·디스크처럼
늘릴 수 없는 자원을 흉내 낸 것이다.

| 재는 값 | 뜻 |
|---|---|
| 처리량 λ | 초당 완료한 요청 수 |
| 평균 응답 W | 요청 하나가 시작해서 끝날 때까지 걸린 시간 |
| L = λ × W | 리틀의 법칙으로 역산한, 계 안에 머문 평균 요청 수 |

워커가 쉬지 않고 요청을 던지는 **닫힌 계**라서 계 안의 요청 수는 항상 풀 크기와
같다. 그래서 `L = λW` 로 나온 값이 풀 크기에 맞는지로 측정 자체를 검산할 수 있다.

## 바꿔 볼 값

| 값 | 바꾸면 |
|---|---|
| `SERVICE_CAPACITY` | 백엔드 한도. 키우면 처리량이 꺾이는 지점이 같이 밀려난다 |
| `SERVICE_TIME` | 한 건 처리 시간. 이론상 최대 처리량이 `한도 / 처리시간` 으로 바뀐다 |
| `JOBS_PER_RUN` | 요청 수. 줄이면 빨리 끝나지만 측정이 흔들린다 |
| `POOL_SIZES` | 재 볼 풀 크기 목록 |

## 측정값에 관해

시간 측정이라 **절대값은 환경마다 다르다.** 같아야 하는 것은 구조다.
풀 크기가 백엔드 한도를 넘어선 뒤로 처리량이 더 늘지 않고, 평균 응답시간이
풀 크기에 거의 비례해 늘며, `L = λW` 가 풀 크기와 맞는 것.

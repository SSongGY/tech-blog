스키마와 데이터 — 아래 질의는 전부 이 표를 대상으로 한다
================================================================
[member]  4행
  컬럼      | 타입    | 제약
  ----------+---------+---------
  member_id | INTEGER | PK
  login     | TEXT    | NOT NULL
  secret    | TEXT    | NOT NULL
  role      | TEXT    | NOT NULL

  member_id | login | secret    | role
  ----------+-------+-----------+-------
          1 | kim   | hash-aaaa | admin
          2 | lee   | hash-bbbb | member
          3 | park  | hash-cccc | member
          4 | choi  | hash-dddd | member

================================================================
1. 문자열을 이어 붙여 만든 질의 — 정상 입력일 때는 잘 돈다
================================================================
  SQL   : SELECT login, role FROM member WHERE login = 'kim'
  결과  : 1행 [('kim', 'admin')]

================================================================
2. 같은 코드에 따옴표가 든 입력을 넣으면
================================================================
  입력  : "' OR '1'='1"
  SQL   : SELECT login, role FROM member WHERE login = '' OR '1'='1'
  결과  : 4행 [('kim', 'admin'), ('lee', 'member'), ('park', 'member'), ('choi', 'member')]

  → 조건이 항상 참이 되어 표 전체가 나왔다

================================================================
3. 문장을 하나 더 붙이려는 시도 — execute 는 한 문장만 받는다
================================================================
  입력  : "x'; DROP TABLE member; --"
  SQL   : SELECT login, role FROM member WHERE login = 'x'; DROP TABLE member; --'
  결과  : ProgrammingError: You can only execute one statement at a time.

  → 다만 '한 문장 안에서 조건을 바꾸는' 2번은 그대로 통한다

================================================================
4. 작은따옴표를 두 개로 바꾸는 이스케이프 — 2번은 막힌다
================================================================
  이스케이프 결과: "'' OR ''1''=''1"
  SQL   : SELECT login, role FROM member WHERE login = ''' OR ''1''=''1'
  결과  : 0행 []

================================================================
5. 그런데 따옴표가 없는 자리는 이스케이프가 닿지 않는다
================================================================
  입력  : '0 OR 1=1'  (이스케이프해도 그대로: '0 OR 1=1')
  SQL   : SELECT login, role FROM member WHERE member_id = 0 OR 1=1
  결과  : 4행 [('kim', 'admin'), ('lee', 'member'), ('park', 'member'), ('choi', 'member')]

  → 숫자 자리는 따옴표로 감싸지 않으므로 따옴표를 고쳐도 소용이 없다

================================================================
6. 바인딩 — 같은 입력을 그대로 넘긴다
================================================================
  SQL   : SELECT login, role FROM member WHERE login = ?
  바인딩: ('kim',)
  결과  : 1행 [('kim', 'admin')]

  SQL   : SELECT login, role FROM member WHERE login = ?
  바인딩: ("' OR '1'='1",)
  결과  : 0행 []

  SQL   : SELECT login, role FROM member WHERE login = ?
  바인딩: ("x'; DROP TABLE member; --",)
  결과  : 0행 []

  SQL   : SELECT login, role FROM member WHERE member_id = ?
  바인딩: ('0 OR 1=1',)
  결과  : 0행 []

  → 값이 문법으로 해석되지 않으므로 '찾는 값이 없다'로 끝난다

================================================================
7. 추적 콜백이 보여 주는 문장 — 바인딩은 이스케이프를 대신해 준다
================================================================
  [1] 문자열 조합, [2] 바인딩. 콜백이 주는 것은 값을 끼워 넣어 복원한
  '확장 문장'이고, 엔진이 실제로 파싱한 것은 [2]의 경우 ? 가 든 쪽이다.
  [1] SELECT login FROM member WHERE login = '' OR '1'='1'
  [2] SELECT login FROM member WHERE login = ''' OR ''1''=''1'

================================================================
8. 바인딩으로 안 되는 자리 — 식별자는 값이 아니다
================================================================
  SQL   : SELECT login FROM member ORDER BY ?
  바인딩: ('role',)
  결과  : 4행 [('choi',), ('kim',), ('lee',), ('park',)]

  → 에러는 안 나지만 role 로 정렬되지 않았다. 바인딩된 값은 컬럼이 아니라
     문자열 상수 하나로 해석되어 모든 행의 정렬 키가 같아진다
  SQL   : SELECT login FROM ?
  바인딩: ('member',)
  결과  : OperationalError: near "?": syntax error

  SQL   : SELECT login, role FROM member ORDER BY role, member_id
  결과  : 4행 [('kim', 'admin'), ('lee', 'member'), ('park', 'member'), ('choi', 'member')]

  허용 목록 밖 입력 'member_id; DROP TABLE member' → 통과 여부: False

================================================================
9. 표가 아직 그대로인지 확인
================================================================
  SQL   : SELECT COUNT(*) FROM member
  결과  : 1행 [(4,)]

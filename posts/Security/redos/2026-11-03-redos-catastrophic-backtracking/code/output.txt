2. 같은 입력이라도 매칭에 성공하면 한 번에 끝난다
==================================================================
  n=20  0.000004초  매칭

  n=28  0.000000초  매칭

4. 다항 폭발 — 끝 공백을 찾는 \s+$ 는 n² 으로 는다
==================================================================
  식: '\s+$' (trim 대용으로 흔히 쓰는 식).  입력: 공백×n 뒤에 'x'
       n      시간(초)     직전 대비
    5000     0.0649         -
   10000     0.2605     × 4.0
   20000     1.0453     × 4.0
   40000     4.2020     × 4.0
  → n 이 2배면 시간은 4배. 지수는 아니지만 길이 제한 없이는 역시 멈춘다

==================================================================
5. 길이 제한이 막는 것과 못 막는 것
==================================================================
  지수 식 + 길이 30          54.6836초
  다항 식 + 길이 30           0.0000초
  → 다항 식은 길이 제한으로 충분하다. 지수 식은 30자도 못 버틴다

==================================================================
6. 식을 고친다 — 분할이 하나뿐이면 백트래킹할 것이 없다
==================================================================
  a+$              n=40  0.000001초  — 중첩을 푼다: (a+)+ 와 같은 언어를 받는다
  (a++)+$          n=40  0.000001초  — 소유 한정자 a++ (Python 3.11+): 한 번 먹은 글자를 돌려주지 않는다
  (?>a+)+$         n=40  0.000002초  — 원자 그룹 (?>...) (Python 3.11+): 그룹 안으로 되돌아가지 않는다
  \w+(\s\w+)*$     n=40  0.000002초  — (\w+\s?)* 를 고친 것: 공백을 필수로 두어 분할을 하나로

==================================================================
7. 타임아웃 — 표준 re 에는 없고, 스레드로 감싸도 제때 못 돌아온다
==================================================================
  join(timeout=0.1) 이 실제로 돌아오기까지 1.704초
  → 매칭 루프가 C 안에서 GIL 을 쥔 채 돌아, 주 스레드가 0.1초 뒤에 깨어나지 못한다

8. 다른 엔진 — 폭발하는 식이 다르고, timeout 은 실제로 끊는다
==================================================================
  regex 2026.9.29
  식              n     re(초)   regex(초)
  (a+)+$        26    1.7179     0.0015
  (a|a)*$       24    0.8613     2.1716
  → (a+)+ 는 regex 가 접어서 즉시 끝내지만, (a|a)* 는 양쪽 다 폭발한다
  regex.fullmatch((a|a)*$, timeout=0.1) → TimeoutError: regex timed out  (0.100초 만에 중단)

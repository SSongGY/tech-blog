1. 로그아웃 — 다음 요청이 어떻게 되는가
------------------------------------------------------------------
  [세션] 로그인   -> 쿠키에 담긴 값 LwnrDyoBMc5azZfA…
  [세션] 요청     -> {'user': 'kim', 'role': 'admin'}
  [세션] 로그아웃 -> 서버에서 세션을 지운다
  [세션] 요청     -> None
    (지운 순간부터 참조할 것이 없다. 다음 요청에서 바로 막힌다)

  [JWT ] 로그인   -> 토큰 224바이트 발급
  [JWT ] 요청     -> {'sub': 'kim', 'role': 'admin', 'iat': 1793269208, 'exp': 1793270108, 'jti': '3998d504-2d31-41f0-9251-cdb208599aa9'}
  [JWT ] 로그아웃 -> 클라이언트가 토큰을 버린다. 서버는 할 일이 없다
  [JWT ] 요청     -> {'sub': 'kim', 'role': 'admin', 'iat': 1793269208, 'exp': 1793270108, 'jti': '3998d504-2d31-41f0-9251-cdb208599aa9'}
    (그대로 통과한다. exp 까지 899초 남았다)

------------------------------------------------------------------
2. 권한 강등 — 관리자에서 일반 사용자로 내렸을 때
------------------------------------------------------------------
  [세션] 강등 후 요청 -> {'user': 'kim', 'role': 'member'}
    (다음 요청이 서버가 들고 있는 값을 읽는다)

  [JWT ] 강등 처리 -> 사용자 표의 role 을 member 로 바꿨다
  [JWT ] 강등 후 요청 -> role=admin
    (토큰에 박힌 값이라 바뀌지 않는다. 사용자 표를 읽지 않으면 모른다)

------------------------------------------------------------------
3. 보완책 세 가지 — 무엇을 되돌려 받고 무엇을 내주는가
------------------------------------------------------------------
  (가) 거부 목록(jti)  -> 서명 통과: True · 거부 목록에 있음: True
       되돌려 받는 것: 즉시 취소
       내주는 것: 매 요청마다 저장소 조회. 무상태가 아니게 된다

  (나) 짧은 수명(1초)  -> 발급 직후 검증
       True
       1.2초 뒤 검증
    거부: ExpiredSignatureError: Signature has expired
       False
       되돌려 받는 것: 취소가 반영되기까지의 창이 짧아진다
       내주는 것: 재발급 토큰을 서버가 보관해야 한다. 역시 상태다

  (다) 토큰 버전       -> 토큰 ver=1 · 현재 ver=2
       낡은 토큰인가: True
       되돌려 받는 것: 사용자 단위 일괄 취소
       내주는 것: 매 요청마다 사용자 표 조회. 세션 조회와 같은 비용이다

4. 검증 비용 — 상태를 없앤 대가로 무엇을 치르는가
------------------------------------------------------------------
  20000회 반복
    세션 조회(메모리 딕셔너리)  0.005초
    JWT 검증 HS256             0.202초
    JWT 검증 RS256             0.790초

  요청마다 실려 가는 크기
    세션 ID          32바이트
    JWT (HS256)     224바이트
    JWT (RS256)     440바이트

5. alg 를 none 으로 바꾼 토큰 — 라이브러리가 막는가
------------------------------------------------------------------
  위조 토큰: eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJzdWIiOiJr…
  algorithms=['HS256'] 으로 검증:
    거부: InvalidAlgorithmError: The specified alg value is not allowed
    통과했는가: False
  PyJWT 2.10.1 은 허용 목록에 없는 alg 를 거부한다.
  algorithms 를 비우거나 토큰의 alg 를 그대로 믿으면 이 방어가 사라진다.

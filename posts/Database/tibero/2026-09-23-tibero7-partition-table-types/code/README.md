# 예제 코드 — Tibero 7 파티션 테이블 — 종류별로 언제 쓰는가

`partition_types.sql` 하나로 RANGE·INTERVAL·LIST·HASH·RANGE-LIST 복합 파티션을 만들고,
행이 어느 파티션에 들어가는지, 들어갈 곳이 없으면 무엇이 막히는지를 확인한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정, `DBMS_STATS` 실행 권한

**빈 스키마에서 돌린다.** 첫 줄에서 `user_objects` 수를 찍고, 마지막에 다시 찍는다.
스크립트의 `DBMS_STATS.GATHER_TABLE_STATS('TIBERO', ...)`의 첫 인자는 돌리는 계정의 스키마
이름으로 바꾼다.

## 실행

```bash
tbsql -s <사용자>/<비밀번호> @partition_types.sql
```

마지막 카운트가 `0`이면 정리까지 끝난 것이다.

```text
  OBJ_LEFT
----------
         0
```

- 확인 환경: Tibero 7.2 인스턴스 (`v$version`의 `PRODUCT_MAJOR 7`, `PRODUCT_MINOR 2`).
  인용한 매뉴얼은 7.2.6판이라 인스턴스 버전과 다르다.

## 나오는 에러 6개는 전부 의도한 것이다

| 에러 | 무엇을 보여주는가 | 예제 번호 |
|---|---|---|
| `TBR-10018` × 2 | RANGE에 `MAXVALUE`가 없으면 경계 밖 값과 NULL이 들어가지 못한다 | 1 |
| `TBR-10019` | `ROW MOVEMENT` 없이 파티션 키를 바꿔 다른 파티션으로 옮길 수 없다 | 1-D |
| `TBR-10018` × 2 | LIST에 `DEFAULT`가 없으면 목록 밖 값과 NULL이 들어가지 못한다 | 3 |
| `TBR-7230` | LIST 파티션 키는 컬럼 하나만 된다 | 3-B |

이 여섯 개 외에 다른 `TBR-`이 보이면 환경 문제이니 확인이 필요하다.

## tbsql 스크립트 모드의 함정 두 가지

1. **파일 마지막 줄은 `EXIT`다.** 없으면 스크립트를 다 읽고도 `SQL>`에서 기다린다.
2. **줄 끝 주석을 달지 않는다.** 문장 뒤 같은 줄에 `-- 주석`을 붙이면 다음 문장이
   `TBR-8004`로 깨진다. 그래서 설명은 전부 `PROMPT` 줄에 있다.

## 바꿔 볼 값

- 4번의 `PARTITIONS 4`를 `16`으로 바꾼다. 8개일 때의 각 칸이 다시 둘로 나뉘는지 본다.
  `6`이나 `7`로 바꾸면 몇 칸이 8개일 때 크기, 몇 칸이 4개일 때 크기로 남는지 센다.
- 2번의 `INTERVAL`에 `2026-12-15`를 한 건 더 넣는다. 11월 파티션 없이 12월 파티션만 생기는지
  확인하는 자리다.
- 1-E의 두 번째 질의를 `sold_on >= DATE '2026-07-01'`과 같은 뜻의 다른 형태
  (`sold_on BETWEEN ... AND ...`)로 바꿔 `PS`·`PE`가 어떻게 바뀌는지 본다.

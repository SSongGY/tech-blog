# 예제 코드 — Tibero 7 인덱스 종류

> **미검증.** 이 스크립트는 아직 실제로 돌리지 않았다. 글을 쓴 시점(2026-09-28)에
> 검증용 Tibero 인스턴스에 접속할 수 없었다(`TBR-2131`). 문장과 기대 에러는 전부
> Tibero 7.2.6 매뉴얼의 `CREATE INDEX` 예제에서 가져왔다.
> 돌려서 `code/output.txt`를 남기면 글을 `verification: executed`로 올릴 수 있다.

`index_types.sql` 하나로 유일·함수 기반·비트맵·리버스·내림차순 인덱스를 만들고,
매뉴얼이 막는다고 적은 조합 네 가지를 일부러 일으킨 뒤, 사전 뷰에서 각 인덱스가
어떻게 보이는지 조회한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정

**빈 스키마에서 돌린다.** 스크립트가 만드는 이름은 `member_account` 테이블 하나와
그 인덱스들이고, 마지막에 테이블을 지운다.

## 실행

```bash
tbsql -s <사용자>/<비밀번호> @index_types.sql
```

마지막 `OBJ_LEFT`가 시작 때의 `OBJ_BEFORE`와 같으면 정리까지 끝난 것이다.

## 나와야 하는 에러 (매뉴얼 기준)

| 번호 | 에러 | 무엇을 보여주는가 |
|---|---|---|
| 2 | `TBR-10007` | 유일 인덱스에 중복 키를 넣을 수 없다 |
| 3 | `TBR-7124` | 같은 키의 인덱스가 이미 있으면 만들 수 없다 |
| 4 | `TBR-8082` | 결과가 바뀌는 함수(`SYSDATE`)는 키로 쓸 수 없다 |
| 5 | `TBR-7013` | 비트맵 인덱스에 `COMPRESS`를 쓸 수 없다 |

이 네 개와 다른 에러가 나오거나, 이 중 하나가 나오지 않으면 그것이 글에 적을 결과다.

## 돌려서 확인할 것

매뉴얼만으로는 알 수 없어 글에서 "확인하지 못했다"고 적은 부분이다.

- 7번 `user_indexes.index_type`에 비트맵·리버스 인덱스가 어떤 값으로 찍히는가.
  매뉴얼의 값 목록은 `NORMAL`, `FUNCTION-BASED`, `LOB` 세 가지다.
- 8번: 리버스 인덱스를 힌트로 지정했을 때 등호 조건(8-1)과 `BETWEEN` 범위 조건(8-2)의
  실행계획이 어떻게 갈리는가. 8-3은 같은 범위 조건을 일반 인덱스로 찾는 비교 기준이다
  (`SET AUTOTRACE TRACEONLY EXPLAIN`).

## tbsql 스크립트 모드의 함정

- **파일 마지막 줄은 `EXIT`다.** 없으면 `SQL>`에서 기다려 무인 실행이 멈춘다.
- **줄 끝 주석을 달지 않는다.** 설명은 전부 `PROMPT` 줄에 있다.

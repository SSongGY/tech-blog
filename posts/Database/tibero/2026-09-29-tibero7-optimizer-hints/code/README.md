# 예제 코드 — Tibero 7 옵티마이저 힌트

**아직 실행하지 않았다.** 글을 쓴 시점에 검증용 Tibero 인스턴스에 접속할 수 없었다(`TBR-2131`).
인스턴스가 살아나면 이 스크립트를 돌려 `code/output.txt`를 만들고 글을 `executed`로 올린다.

`optimizer_hints.sql` 하나로 매뉴얼이 적은 "힌트가 무시되는 조건"을 하나씩 계획으로 확인한다.

| 장 | 무엇을 보는가 | 매뉴얼이 적은 기대 |
|---|---|---|
| 2 | 힌트 없는 기준 계획 | — |
| 3~4 | 별칭이 있을 때 별칭 / 테이블 이름으로 쓴 힌트 | 별칭을 써야 한다 |
| 5 | `/*`와 `+` 사이에 공백 | `+`는 공백 없이 붙인다 |
| 6 | 힌트 이름 오타 | 주석으로 처리, 오류 없음 |
| 7 | 같은 인덱스에 `INDEX`와 `NO_INDEX` | 둘 다 무시 |
| 8 | 조건에 쓸 수 없는 인덱스 지정 | 쓸 수 없으면 무시 |
| 9 | `LEADING`만 / `ORDERED`와 `LEADING`을 함께 | `ORDERED`가 있으면 `LEADING` 무시 |
| 10 | 인라인 뷰 안의 `NO_MERGE` | 질의 블록마다 힌트 주석 하나 |
| 11 | `IGNORE_ROW_ON_DUPKEY_INDEX` 인덱스 누락 / 지정 | 누락하면 오류, 지정하면 중복 행만 건너뜀 |
| 12 | `EXPLAIN PLAN` + `DBMS_XPLAN.DISPLAY('ALL')` | `ALL`에 OUTLINE(재현용 힌트 목록)이 들어간다 |

**힌트 인자 형태(`FULL(e)`, `INDEX(e 인덱스)`, `LEADING(e d)`)는 매뉴얼 본문 글에서 확인하지 못했다.**
돌려 본 계획으로 인자 형태가 맞는지부터 본다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정, `SET AUTOTRACE`에 필요한 DBA 권한 또는 `PLUSTRACE` 롤

**빈 스키마에서 돌린다.** 스크립트가 만드는 이름은 `hint_dept`, `hint_emp`와 그 인덱스다.

## 실행

```bash
tbsql -s <사용자>/<비밀번호> @optimizer_hints.sql
```

마지막 `OBJ_LEFT`가 `0`이면 정리까지 끝난 것이다.

## 나와야 하는 에러

11장의 첫 `INSERT` 하나다(인덱스를 지정하지 않은 `IGNORE_ROW_ON_DUPKEY_INDEX`). 6장의 오타는 **에러가 나지 않아야** 한다.
12장에서 `PLAN_TABLE`이 없다는 에러가 나면 매뉴얼의 전제(대상 테이블이 미리 있어야 한다)를 확인한다.

## tbsql 스크립트 모드의 함정 두 가지

1. **파일 마지막 줄은 `EXIT`다.** 없으면 `SQL>`에서 기다려 무인 실행이 멈춘다.
2. **줄 끝 주석을 달지 않는다.** 문장 뒤 같은 줄의 `-- 주석`은 다음 문장을 깨뜨린다. 설명은 `PROMPT` 줄에 둔다.
   힌트의 `--+` 형식을 스크립트에서 쓰지 않은 것도 같은 이유다.

# 예제 코드 — Tibero 7 분석 함수의 윈도우 절

`window_clause.sql` 하나로 기본 윈도우, `ROWS`와 `RANGE`의 차이, `LAST_VALUE`의 함정,
그리고 막히는 경우 다섯 가지를 한 번에 확인한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정

**빈 스키마에서 돌린다.** 스크립트가 만드는 이름은 `sale_daily` 하나이고,
같은 이름이 이미 있으면 `TBR-7102`로 막힌다.

## 실행

```bash
tbsql -s <사용자>/<비밀번호> @window_clause.sql
```

마지막 카운트가 `0`이면 정리까지 끝난 것이다.

```text
  OBJ_LEFT
----------
         0
```

- 확인 환경: Tibero 7.2 인스턴스 (`SELECT * FROM v$version`의 `PRODUCT_MAJOR 7`,
  `PRODUCT_MINOR 2`). 인용한 매뉴얼은 7.2.6판이라 인스턴스 버전과 다르다.

## 데이터에 일부러 넣은 두 가지

| 무엇 | 어디 | 무엇을 보여주는가 |
|---|---|---|
| `sale_day` 3이 두 행 | 30, 40 | 정렬 키가 같을 때 `ROWS`와 `RANGE`가 갈린다 |
| 4·6·7일이 비어 있음 | 3 → 5 → 8 | `RANGE`가 값 기준이라 빈 구간을 그대로 반영한다 |

## 나오는 에러 10개는 전부 의도한 것이다

| 에러 | 무엇을 보여주는가 | 예제 번호 |
|---|---|---|
| `TBR-8067` | `RANGE`에 오프셋을 쓰면 정렬 키가 하나여야 한다 | 5 |
| `TBR-8004` | `RANK`에 윈도우 절을 붙일 수 없다 | 7 |
| `TBR-11005` | `RANGE` 오프셋에 음수를 쓸 수 없다 | 8 |
| `TBR-8067` | 윈도우의 시작이 끝보다 뒤일 수 없다 | 9 |
| `TBR-8004` | `ORDER BY` 없이 윈도우 절만 쓸 수 없다 | 10 |
| `TBR-8004` × 5 | `ROW_NUMBER`·`DENSE_RANK`·`LEAD`·`LAG`·`NTILE`도 마찬가지다 | 11 |

이 열 개 외에 다른 `TBR-`이 보이면 환경 문제이니 확인이 필요하다.

## tbsql 스크립트 모드의 함정 두 가지

이 파일의 형식이 왜 이런지에 대한 설명이다.

1. **파일 마지막 줄은 `EXIT`다.** 없으면 스크립트를 다 읽고도 `SQL>`에서 기다려
   무인 실행이 그 자리에서 멈춘다.
2. **줄 끝 주석을 달지 않는다.** 문장 뒤 같은 줄에 `-- 주석`을 붙이면 다음 문장이
   `TBR-8004`로 깨진다. 그래서 이 스크립트의 설명은 전부 `PROMPT` 줄에 있다.

## 바꿔 볼 값

- 3번의 `2 PRECEDING`을 `3 PRECEDING`으로 바꾼다. `ROWS` 쪽은 창이 4행으로 늘 뿐이지만
  `RANGE` 쪽은 8일 행이 보는 구간이 `[5, 8]`로 바뀐다. 어느 행이 새로 들어오는지 센다.
- 8일 행을 지우고 다시 돌리면 `ROWS` 쪽 3행 창은 그대로 유지되지만 `RANGE` 쪽 9일 행은
  혼자 남는다. 창의 크기가 무엇으로 정해지는지 보는 자리다.
- 4번의 `LAST_VALUE`에서 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`을
  `RANGE`로 바꿔도 결과가 같은지 확인해 본다. 양끝이 무한이면 두 방식이 같아진다.

# 예제 코드 — Tibero 7 MERGE 문

`merge_examples.sql` 하나로 UPSERT 기본형, 절 하나만 쓰기, `UPDATE`의 `WHERE`,
`DELETE WHERE`의 판정 시점, 그리고 막히는 경우 세 가지를 한 번에 확인한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정

**빈 스키마에서 돌린다.** 스크립트가 만드는 이름은 `product_master`, `product_feed`
두 개이고, 같은 이름이 이미 있으면 `TBR-7102`로 막힌다.

## 실행

```bash
tbsql <사용자>/<비밀번호> @merge_examples.sql
```

마지막 카운트가 `0`이면 정리까지 끝난 것이다.

```text
  OBJ_LEFT
----------
         0
```

- 확인 환경: Tibero 7.2 인스턴스 (`SELECT * FROM v$version`의 `PRODUCT_MAJOR 7`,
  `PRODUCT_MINOR 2`). 인용한 매뉴얼은 7.2.6판이라 인스턴스 버전과 다르다.

## 각 예제는 ROLLBACK 으로 끝난다

예제마다 같은 초기 상태에서 출발해야 결과를 비교할 수 있으므로, 1번에서 마스터를 채워
`COMMIT`한 뒤 각 `MERGE` 다음에 `ROLLBACK`을 둔다. 단, 피드 테이블에 행을 추가하는
6번과 8번은 `COMMIT`하므로 **그 뒤 예제는 늘어난 피드를 본다.** 9번의 병합 건수가
4인 것은 6번이 넣은 4번 행 때문이다.

## 나오는 에러 3개는 전부 의도한 것이다

| 에러 | 무엇을 보여주는가 | 예제 번호 |
|---|---|---|
| `TBR-8101` | `ON` 절에 쓴 컬럼은 갱신할 수 없다 | 7 |
| `TBR-10021` | 소스에 같은 키가 두 번 있어 타깃 한 행이 두 번 갱신된다 | 8 |
| `TBR-8004` | `WHEN NOT MATCHED BY SOURCE`를 지원하지 않는다 | 10 |

이 셋 외에 다른 `TBR-`이 보이면 환경 문제이니 확인이 필요하다.

## tbsql 스크립트 모드의 함정 두 가지

이 파일의 형식이 왜 이런지에 대한 설명이다.

1. **파일 마지막 줄은 `EXIT`다.** 없으면 스크립트를 다 읽고도 `SQL>`에서 기다려
   무인 실행이 그 자리에서 멈춘다.
2. **줄 끝 주석을 달지 않는다.** 문장 뒤 같은 줄에 `-- 주석`을 붙이면 다음 문장이
   `TBR-8004`로 깨진다. 그래서 이 스크립트의 설명은 전부 `PROMPT` 줄에 있다.

## 바꿔 볼 값

- 5번의 `DELETE WHERE t.stock_qty = 0`을 `DELETE WHERE t.price > 50000`으로 바꿔 본다.
  갱신 후 가격으로 판정하므로 3번(54000 → 49000)이 살아남는 것을 볼 수 있다.
- 6번의 `WHERE t.price <> s.price`를 지우면 4번이 지워진다. 이 한 줄이 삭제 판정을
  건너뛰게 만든다는 것이 6번의 요점이다.
- 9번의 `MAX(price)`를 `MIN(price)`로 바꾸면 2번의 가격이 32000으로 남는다.
  중복을 어떻게 접을지는 문법이 아니라 업무 규칙이다.

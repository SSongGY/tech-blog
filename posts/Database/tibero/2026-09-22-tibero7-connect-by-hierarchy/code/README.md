# 예제 코드 — Tibero 7 계층 질의

`connect_by_examples.sql` 하나로 계층 질의의 기본형, 의사 컬럼 네 가지, 순환 참조 처리,
그리고 조건을 `WHERE`에 두느냐 `CONNECT BY`에 두느냐의 차이를 한 번에 확인한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정

**빈 스키마에서 돌린다.** 스크립트가 만드는 이름은 `emp_org`, `ring_org` 두 개이고,
같은 이름이 이미 있으면 `TBR-7102`로 막힌다.

## 실행

```bash
tbsql <사용자>/<비밀번호> @connect_by_examples.sql
```

마지막 카운트가 `0`이면 정리까지 끝난 것이다.

```text
  OBJ_LEFT
----------
         0
```

- 확인 환경: Tibero 7.2 인스턴스 (`SELECT * FROM v$version`의 `PRODUCT_MAJOR 7`,
  `PRODUCT_MINOR 2`). 인용한 매뉴얼은 7.2.6판이라 인스턴스 버전과 다르다.

## 나오는 에러 3개는 전부 의도한 것이다

| 에러 | 무엇을 보여주는가 | 예제 번호 |
|---|---|---|
| `TBR-10064` | 순환 참조를 만나 순회가 멈춤 | 8, 12 |
| `TBR-8099` | `NOCYCLE` 없이 `CONNECT_BY_ISCYCLE` 사용 | 10 |

이 셋 외에 다른 `TBR-`이 보이면 환경 문제이니 확인이 필요하다.
`TBR-10064`가 8번과 12번 두 번 나오므로 에러 줄은 모두 3줄이다.

## tbsql 스크립트 모드의 함정 두 가지

이 파일의 형식이 왜 이런지에 대한 설명이다.

1. **파일 마지막 줄은 `EXIT`다.** 없으면 스크립트를 다 읽고도 `SQL>`에서 기다려
   무인 실행이 그 자리에서 멈춘다.
2. **줄 끝 주석을 달지 않는다.** 문장 뒤 같은 줄에 `-- 주석`을 붙이면 다음 문장이
   `TBR-8004`로 깨진다. 그래서 이 스크립트의 주석은 전부 자기 줄에 있다.

## 바꿔 볼 값

- 4번과 5번의 `emp_name <> '오세훈'`을 `dept_name <> '개발'`로 바꿔 본다.
  `WHERE` 쪽은 개발팀만 빠지고 그 아래가 남지만, `CONNECT BY` 쪽은 가지가 잘린다.
- 11번의 `LEVEL <= 3`을 `LEVEL <= 2`로 낮추면 순환 테이블에서 돌아오는 행이 줄어든다.
  `WHERE`로 옮기면(12번) 몇으로 바꾸든 `TBR-10064`다.
- 14번의 `PRIOR dept_name = dept_name`을 떼고 `START WITH emp_id = 1`로 바꾸면
  부서가 바뀌는 경계에서 가지가 끊기는 것을 볼 수 있다.

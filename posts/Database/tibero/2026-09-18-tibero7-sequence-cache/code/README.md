# 예제 코드 — Tibero 7 시퀀스

`sequence_examples.sql` 하나로 시퀀스의 기본값, 제약, 에러, identity 컬럼까지 한 번에 확인한다.

## 요구 사항

- Tibero 7 인스턴스와 `tbsql` 클라이언트
- 객체를 만들고 지울 수 있는 계정

**빈 스키마에서 돌리는 것을 권한다.** 스크립트가 만드는 이름은 아래와 같고,
같은 이름이 이미 있으면 `TBR-7102`로 막힌다.

```
테이블   order_item, emp_identity
시퀀스   order_seq, countdown_seq, slot_seq, tiny_seq, ring_seq, invoice_seq
```

## 실행

```bash
tbsql <사용자>/<비밀번호> @sequence_examples.sql
```

마지막 두 카운트가 `0`이면 정리까지 끝난 것이다.

```text
  SEQ_LEFT
----------
         0
  TAB_LEFT
----------
         0
```

## tbsql 스크립트 모드의 두 가지 함정

이 파일의 형식이 왜 이런지에 대한 설명이다. 둘 다 Tibero 7.2.6에서 재현했다.

### 1. 끝에 `EXIT`가 없으면 프롬프트에서 대기한다

`tbsql ... @script.sql`은 스크립트를 다 읽고도 종료하지 않고 `SQL>`에서 기다린다.
스케줄러나 CI에서 돌리면 그 자리에서 멈춘다. **파일 마지막 줄은 `EXIT`다.**

### 2. 문장 뒤 같은 줄의 주석이 다음 문장을 깨뜨린다

기대값을 코드 옆에 적으면 읽기 좋지만, `tbsql`에서는 그 주석이 다음 문장을 삼킨다.

```sql
CREATE SEQUENCE p1;
SELECT p1.NEXTVAL FROM dual;        -- 줄 끝 주석
SELECT p1.NEXTVAL FROM dual;
DROP SEQUENCE p1;
EXIT
```

```text
Sequence 'P1' created.
TBR-8004: Syntax error.
at line 2, column 1 of null:
SELECT p1.NEXTVAL FROM dual
^
Sequence 'P1' dropped.
```

주석을 독립된 줄로 옮기면 정상이다.

```sql
CREATE SEQUENCE p2;
-- 독립 줄 주석
SELECT p2.NEXTVAL FROM dual;
SELECT p2.NEXTVAL FROM dual;
DROP SEQUENCE p2;
EXIT
```

```text
Sequence 'P2' created.
   NEXTVAL
----------
         1
   NEXTVAL
----------
         2
Sequence 'P2' dropped.
```

그래서 이 스크립트의 모든 주석은 자기 줄에 있다.

## 나오는 에러 8개는 전부 의도한 것이다

제약을 보여주려고 일부러 실패시키는 문장들이다. 이 8개 외에 다른 `TBR-`이 보이면
환경 문제이니 확인이 필요하다.

| 에러 | 무엇을 보여주는가 |
|---|---|
| `TBR-6003` | `NEXTVAL` 없이 `CURRVAL` 호출 |
| `TBR-7136` | 오름차순 `CYCLE`에 `MAXVALUE` 누락 |
| `TBR-7340` | 캐시 크기가 한 사이클보다 큼 |
| `TBR-7424` | `INCREMENT`가 `MAXVALUE - MINVALUE`보다 큼 |
| `TBR-7615` | `CREATE`에서 `RESTART` 사용 |
| `TBR-6004` | `NOCYCLE` 시퀀스가 범위를 다 씀 |
| `TBR-7008` | `ALTER`에서 `START WITH` 사용 |
| `TBR-8162` | `ALWAYS` identity 컬럼에 값 직접 삽입 |

## 바꿔가며 확인할 것

- 1번의 `CREATE SEQUENCE order_seq`에 `CACHE`를 명시해 보고, 10번의 `LAST_NUMBER`가
  캐시 크기에 따라 어떻게 앞서가는지 비교한다
- 8번의 `invoice_seq`에 `MINVALUE 1000`을 추가하면 `RESTART`가 1이 아니라 1000으로
  돌아간다. `RESTART`가 `MINVALUE` 기준이라는 것을 이렇게 확인할 수 있다
- 9번의 `GENERATED ALWAYS`를 `GENERATED BY DEFAULT`로 바꾸면 `TBR-8162`가 사라진다

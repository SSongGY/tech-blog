# 예제 코드 — 복합 인덱스의 컬럼 순서

`order_probe.py` 하나로 끝난다. 표준 라이브러리만 쓴다. 메모리 DB에 30만 행을 만들고
같은 두 컬럼으로 순서만 바꾼 인덱스를 각각 `INDEXED BY`로 고정해 비교한다.

네 가지 케이스를 돌린다.

1. 등치 + 범위 조건 — 컬럼 순서가 훑는 범위를 몇 배 바꾸는지
2. 등치 + 등치 조건 — `WHERE` 절에 쓴 순서가 영향을 주는지
3. 선행 컬럼을 생략했을 때 — 인덱스를 어떻게 쓰는지
4. `ORDER BY` — 두 번째 컬럼이 정렬 단계를 없애는지

## 실행

```bash
python order_probe.py
```

환경: Python 3.13.5, SQLite 3.49.1.

## 바꿔볼 값

| 상수 | 기본값 | 바꾸면 |
|---|---|---|
| `ROW_COUNT` | 300,000 | 행 수에 따라 범위 차이의 절대값이 비례해 커진다 |
| `STATUS_WEIGHTS` | 70 / 25 / 5 | 선행 컬럼의 선택도를 바꾼다. 균등하게 두면 차이가 줄어든다 |
| `CUTOFF_DAY` | 150 (전체 180일 중) | 범위 조건이 걸러내는 폭을 바꾼다 |
| `CHANNEL_NAMES` | 12개 | 서로 다른 값을 크게 늘리면 3번 케이스의 스킵 스캔이 사라질 수 있다 |
| `REPEAT_COUNT` | 5 | 반복 횟수. 최솟값을 쓴다 |

`conn.execute("ANALYZE")` 줄을 지우고 돌리면 3번 케이스의 계획이 달라진다.
통계 없이는 옵티마이저가 선행 컬럼의 값 개수를 알 수 없기 때문이다.

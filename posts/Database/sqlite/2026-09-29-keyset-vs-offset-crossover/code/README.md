# 예제 코드 — 커서 기반 페이지네이션이 OFFSET을 이기는 지점

메모리 DB에 글 20만 행을 넣고(한 초에 4개씩 몰려 `created_at`에 동점이 있다)
`(created_at, id)` 인덱스를 만든다. 최신순 페이지를 OFFSET으로 읽을 때와 커서로 읽을 때를
페이지 깊이별로 비교한다. 외부 의존성 없이 파이썬 표준 라이브러리만 쓴다.

| 장 | 무엇을 보는가 |
|---|---|
| 1 | OFFSET과 키셋 세 가지 조건의 실행 계획 |
| 2 | 건너뛴 행 수별 가상 머신 명령 개수·시간 중앙값, 그리고 OFFSET과 같은 행을 돌려주는지 |
| 3 | 커서로 첫 페이지부터 끝까지 넘겼을 때 받은 행 수 |
| 4 | 인덱스를 지운 뒤 같은 비교 |
| 5 | 1·2페이지 사이에 새 글이 들어왔을 때 두 방식의 2페이지 |

## 실행

```bash
python keyset_vs_offset.py
```

## 바꿔볼 값

- `BASE_EPOCH + (i * 7919 % ROW_COUNT) // 4`의 `4`를 `1`로 바꾸면 동점이 사라진다.
  3장에서 `created_at 만 비교`의 빠진 행이 0이 되는지 본다.
- `DEPTHS`에 값을 더 넣으면 OR 조건과 OFFSET의 명령 개수가 어디서부터 같이 늘어나는지 촘촘히 볼 수 있다.
- `PAGE_SIZE`를 100으로 키우면 얕은 페이지에서 OFFSET과 키셋의 차이가 거의 없어지는지 본다.

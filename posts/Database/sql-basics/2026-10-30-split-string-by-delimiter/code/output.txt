스키마와 데이터 — 아래 질의는 전부 이 표를 대상으로 한다
================================================================
[article]  4행
  컬럼  | 타입    | 제약
  ------+---------+---------
  id    | INTEGER | PK
  title | TEXT    | NOT NULL
  tags  | TEXT    | NOT NULL

  id | title                 | tags
  ---+-----------------------+----------------
   1 | 인덱스가 안 타는 이유 | db,index,sql
   2 | 컨테이너 격리 입문    | linux,container
   3 | 느린 쿼리 잡기        | db,performance
   4 | 정규화 다시 보기      | db

[article_tag]  8행
  컬럼       | 타입    | 제약
  -----------+---------+------------
  article_id | INTEGER | PK NOT NULL
  tag        | TEXT    | PK NOT NULL

  article_id | tag
  -----------+------------
           1 | db
           1 | index
           1 | sql
           2 | container
           2 | linux
           3 | db
           3 | performance
           4 | db

[인덱스]
  이름                | 대상 표     | 정의
  --------------------+-------------+-----------------------------------------------------
  idx_article_tag_tag | article_tag | CREATE INDEX idx_article_tag_tag ON article_tag(tag)


================================================================
1. LIKE 로 태그를 찾으면 무엇이 걸리는가
================================================================

-- tags LIKE '%db%' — 'db' 를 찾았는데
   (1, '인덱스가 안 타는 이유', 'db,index,sql')
   (3, '느린 쿼리 잡기', 'db,performance')
   (4, '정규화 다시 보기', 'db')

-- tags LIKE '%in%' — 부분 문자열이 그대로 걸린다
   (1, 'db,index,sql')
   (2, 'linux,container')

================================================================
2. 재귀 CTE 로 펼치기
================================================================

-- article 한 행이 태그 수만큼 행이 된다
   (1, 'db')
   (1, 'index')
   (1, 'sql')
   (2, 'container')
   (2, 'linux')
   (3, 'db')
   (3, 'performance')
   (4, 'db')

-- 펼친 결과를 WHERE 로 거르면 정확히 맞는 것만 남는다
   (1, 'db')
   (3, 'db')
   (4, 'db')

================================================================
3. json_each 로 펼치기
================================================================

-- 문자열을 JSON 배열 모양으로 만들어 넘긴다
   (1, 'db')
   (1, 'index')
   (1, 'sql')
   (2, 'container')
   (2, 'linux')
   (3, 'db')
   (3, 'performance')
   (4, 'db')

================================================================
4. 경계값에서 둘이 어떻게 갈리는가
================================================================

  빈 문자열: ''
    재귀 CTE  -> []
    json_each -> ['']

  태그 하나: 'db'
    재귀 CTE  -> ['db']
    json_each -> ['db']

  뒤에 구분자: 'db,'
    재귀 CTE  -> ['db']
    json_each -> ['db', '']

  구분자 연속: 'db,,sql'
    재귀 CTE  -> ['db', 'sql']
    json_each -> ['db', '', 'sql']

  공백 섞임: 'db, sql'
    재귀 CTE  -> ['db', ' sql']
    json_each -> ['db', ' sql']

  따옴표 포함: 'say"hi,db'
    재귀 CTE  -> ['say"hi', 'db']
    json_each -> OperationalError: malformed JSON

================================================================
5. 쪼개 저장한 쪽과 실행계획 비교
================================================================

-- 펼쳐서 거르기 — article 전체를 읽는다
QUERY PLAN
|--CO-ROUTINE split
|  |--SETUP
|  |  `--SCAN article
|  `--RECURSIVE STEP
|     `--SCAN split
|--SCAN split
`--USE TEMP B-TREE FOR ORDER BY

-- 쪼개 저장한 표 — tag 인덱스를 탄다
QUERY PLAN
`--SEARCH article_tag USING INDEX idx_article_tag_tag (tag=?)

-- 두 질의의 결과가 같은지 확인
   펼쳐서 거르기 : [1, 3, 4]
   쪼개 저장     : [1, 3, 4]

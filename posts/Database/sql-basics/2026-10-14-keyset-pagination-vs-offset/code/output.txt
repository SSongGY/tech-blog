1. 같은 2페이지를 두 가지 방법으로 읽는다
================================================================
1페이지 (OFFSET 0 LIMIT 4)
  (12, '2026-10-11 19:25', '트리거')
  (11, '2026-10-10 12:00', 'UPSERT')
  (10, '2026-10-09 15:10', '재귀 CTE')
  (9, '2026-10-08 07:45', '윈도 함수')
  → 마지막 행의 커서: posted_at='2026-10-08 07:45', id=9

2페이지 — OFFSET 4 LIMIT 4
  (8, '2026-10-07 21:00', '커버링 인덱스')
  (7, '2026-10-06 13:20', '부분 인덱스')
  (6, '2026-10-05 10:05', '통계 수집')
  (5, '2026-10-04 17:40', '실행계획 읽기')

2페이지 — 키셋 (posted_at, id) < ('2026-10-08 07:45', 9)
  (8, '2026-10-07 21:00', '커버링 인덱스')
  (7, '2026-10-06 13:20', '부분 인덱스')
  (6, '2026-10-05 10:05', '통계 수집')
  (5, '2026-10-04 17:40', '실행계획 읽기')

두 결과가 같은가: True

행 값 비교 대신 OR 로 풀어 쓴 결과도 같은가: True

================================================================
2. 1페이지를 읽은 뒤 2페이지를 읽기 전에 새 글이 올라오면
================================================================
1페이지를 읽은 직후 — 독자가 본 id: [12, 11, 10, 9]
그 사이 id=99 가 목록 맨 앞에 들어왔다.

2페이지 — OFFSET 4: [9, 8, 7, 6]
           1페이지와 겹치는 id: [9]
2페이지 — 키셋          : [8, 7, 6, 5]
           1페이지와 겹치는 id: []

================================================================
5. 정렬키가 유일하지 않으면 — id 를 떼면 무슨 일이 생기는가
================================================================
같은 posted_at 을 가진 묶음: [('2026-10-01 09:00', 2)]

커서를 posted_at 하나로만 잡고 '< 커서' 로 다음 페이지를 읽으면
  posted_at < '2026-10-01 09:00' → []
  같은 시각의 id=1, id=2 가 통째로 사라진다.

'<=' 로 바꾸면 이번에는 이미 본 행이 다시 나온다
  posted_at <= '2026-10-01 09:00' → [(2, '2026-10-01 09:00'), (1, '2026-10-01 09:00')]

id 를 정렬키에 더해 커서를 (posted_at, id) 로 잡으면 둘 다 생기지 않는다
  (posted_at, id) < ('2026-10-01 09:00', 2) → [(1, '2026-10-01 09:00')]

  건너뛴 행 |    OFFSET | 키셋(행 값) |  키셋(OR) | 세 결과가 같은가
  ----------+-----------+-------------+-----------+-----------------
          0 |    0.02ms |      0.02ms |   0.02ms | True
      1,000 |    0.03ms |      0.02ms |   0.07ms | True
     10,000 |    0.16ms |      0.02ms |   0.46ms | True
     50,000 |    0.75ms |      0.02ms |   2.26ms | True
    100,000 |    1.39ms |      0.02ms |   4.37ms | True
    199,980 |    2.88ms |      0.03ms |   9.28ms | True

4. 실행계획 — 같은 인덱스를 쓰는데 하는 일이 다르다
================================================================
OFFSET 방식
QUERY PLAN
`--SCAN article USING INDEX idx_article_posted

키셋 방식 (행 값 비교)
QUERY PLAN
`--SEARCH article USING INDEX idx_article_posted (posted_at<?)

키셋 방식 (OR 로 풀어 쓴 것)
QUERY PLAN
`--SCAN article USING INDEX idx_article_posted

# 키셋 페이지네이션 — OFFSET을 버리는 이유

OFFSET 방식과 키셋 방식을 같은 데이터에서 비교한다. 외부 의존성이 없고
표준 라이브러리의 `sqlite3` 모듈만 쓴다.

## 실행

```bash
python keyset_pagination.py
```

## 파일

| 파일 | 하는 일 |
|---|---|
| `keyset_pagination.py` | 12행짜리 작은 표와 20만 행짜리 큰 표를 메모리에 만들어 다섯 가지를 확인한다 |
| `dbshow.py` | 질의 결과 앞에 표 정의와 데이터를 찍는 도우미 (`references/dbshow.py` 사본) |
| `output.txt` | 실제 실행 기록. `blog.py run-example` 이 만든다 |

## 바꿔 볼 값

| 상수 | 기본값 | 바꾸면 |
|---|---|---|
| `BIG_ROWS` | `200_000` | 줄이면 OFFSET 깊이에 따른 차이가 덜 벌어진다 |
| `BIG_PAGE` | `20` | 한 페이지 크기. 키셋 쪽 시간은 여기에만 비례한다 |
| `REPEAT` | `7` | 측정 반복 횟수. 중앙값을 쓰므로 홀수가 낫다 |
| `PAGE_SIZE` | `4` | 작은 표의 페이지 크기 |

인덱스를 지우고 돌리면 (`CREATE INDEX` 줄을 주석 처리) 키셋 방식도
`SCAN` 으로 떨어지면서 이점이 사라진다. 키셋이 빠른 것은 인덱스가
정렬 순서를 이미 갖고 있기 때문이지 `WHERE` 절 자체 때문이 아니다.

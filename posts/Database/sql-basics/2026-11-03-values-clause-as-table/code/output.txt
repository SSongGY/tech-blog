스키마와 데이터 — 아래 질의는 전부 이 표를 대상으로 한다
================================================================
[sale]  4행
  컬럼    | 타입    | 제약
  --------+---------+---------
  sale_id | INTEGER | PK
  ch      | TEXT    | NOT NULL
  amount  | INTEGER | NOT NULL

  sale_id | ch | amount
  --------+----+-------
        1 | ON |    100
        2 | OF |    200
        3 | ON |     50
        4 | XX |     10


==============================================================
1. 단독 VALUES 는 그 자체로 결과 집합이다
==============================================================
컬럼 이름: ['column1', 'column2']
행       : [('ON', '온라인'), ('OF', '오프라인')]

==============================================================
2. CTE 로 이름을 붙이면 표가 된다
==============================================================
컬럼 이름: ['label', 'total']
  모바일        0
  오프라인     200
  온라인      150

==============================================================
3. 같은 일을 CASE 로 하면 두 가지가 빠진다
==============================================================
  None      10
  오프라인     200
  온라인      150
  → 매출이 0인 '모바일' 행이 없고, 코드표에 없는 'XX' 가 NULL 로 섞였다

==============================================================
4. 코드표에 없는 값만 뽑아낸다
==============================================================
  코드표에 없는 값: ['XX']

==============================================================
5. 질의 계획 — VALUES 목록에는 인덱스가 없다
==============================================================
-- big.ch 에 인덱스가 없을 때
QUERY PLAN
|--CO-ROUTINE channel
|  `--SCAN 3 CONSTANT ROWS
|--SCAN channel
|--SCAN big
`--USE TEMP B-TREE FOR GROUP BY
-- big.ch 에 인덱스를 만든 뒤
QUERY PLAN
|--CO-ROUTINE channel
|  `--SCAN 3 CONSTANT ROWS
|--SCAN channel
|--SEARCH big USING COVERING INDEX ix_big_ch (ch=?)
`--USE TEMP B-TREE FOR GROUP BY

==============================================================
6. VALUES 리터럴에는 타입 친화성이 없다
==============================================================
  INTEGER 컬럼 = VALUES 의 문자 '1'       매칭 1건
  VALUES 의 숫자 1 = VALUES 의 문자 '1'    매칭 0건

==============================================================
7. 컬럼 이름은 CTE 에서만 붙는다
==============================================================
  에러 SELECT * FROM (VALUES (1,'x')) AS n(a, b)        near "(": syntax error
  OK   SELECT * FROM (VALUES (1,'x')) AS n              ['column1', 'column2']
  OK   WITH n(a, b) AS (VALUES (1,'x')) SELECT * FROM n ['a', 'b']

==============================================================
8. MATERIALIZED 힌트를 붙이면 계획이 바뀐다
==============================================================
  (힌트 없음)          첫 줄: CO-ROUTINE channel
  MATERIALIZED     첫 줄: MATERIALIZE channel

==============================================================
9. 리터럴로 적는 행 수와 바인딩 파라미터 수는 상한이 다르다
==============================================================
  OK   리터럴 10000행 — COUNT(*) = 10000
  OK   리터럴 100000행 — COUNT(*) = 100000
  OK   파라미터 32766개
  에러 파라미터 32767개 — too many SQL variables

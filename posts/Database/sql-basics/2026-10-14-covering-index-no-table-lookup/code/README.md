# 커버링 인덱스 — 테이블을 안 보고 끝내기

같은 질의에 인덱스 구성만 바꿔 가며 실행계획과 소요 시간, 디스크 증가를 잰다.
외부 의존성 없이 표준 라이브러리의 `sqlite3` 모듈만 쓴다.

## 실행

```bash
python covering_index.py
```

## 파일

| 파일 | 하는 일 |
|---|---|
| `covering_index.py` | 12행짜리 표로 실행계획을, 10만 행 파일 DB로 시간과 페이지 수를 잰다 |
| `dbshow.py` | 질의 결과 앞에 표 정의와 데이터를 찍는 도우미 (`references/dbshow.py` 사본) |
| `output.txt` | 실제 실행 기록. `blog.py run-example` 이 만든다 |
| `covering.db` | 측정용 파일 DB. 돌릴 때마다 새로 만든다 (gitignore) |

페이지 수를 재려면 메모리가 아니라 **파일** DB여야 하므로 2부는 `covering.db` 를
만든다. `VACUUM` 을 끼운 것은 인덱스를 지운 자리를 돌려받아야 증감이 그대로
보이기 때문이다.

## 바꿔 볼 값

| 상수 | 기본값 | 바꾸면 |
|---|---|---|
| `BIG_ROWS` | `100_000` | 줄이면 커버링 여부에 따른 시간 차가 덜 벌어진다 |
| `RANGE_ARGS` | 4만 건 범위 | 범위를 좁히면 표를 보러 가는 횟수가 줄어 차이가 작아진다 |
| `SCHEMA` 의 `bio` 길이 | 120자 | 짧게 하면 표가 작아져 표를 보러 가는 비용이 싸진다 |
| `PAGE_SIZE` | `4096` | 페이지 수가 통째로 달라진다. 용량(MB)으로 봐야 비교가 된다 |

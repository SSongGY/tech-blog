스키마와 데이터 — 아래 질의는 전부 이 표를 대상으로 한다
================================================================
[member]  2행
  컬럼        | 타입    | 제약
  ------------+---------+-------------------
  id          | INTEGER | PK
  email       | TEXT    | NOT NULL
  nickname    | TEXT    |
  login_count | INTEGER | NOT NULL DEFAULT 0

  id | email         | nickname | login_count
  ---+---------------+----------+------------
   1 | a@example.com | 도윤     |           3
   2 | b@example.com | 서준     |           1

[stock]  2행
  컬럼       | 타입    | 제약
  -----------+---------+-------------------
  sku        | TEXT    | PK
  name       | TEXT    | NOT NULL
  qty        | INTEGER | NOT NULL DEFAULT 0
  memo       | TEXT    |
  updated_at | TEXT    | NOT NULL

  sku   | name | qty | memo     | updated_at
  ------+------+-----+----------+-----------
  A-100 | 볼펜 |  10 | 창고 2층 | 2026-10-01
  B-200 | 공책 |   5 | NULL     | 2026-10-01


== 1. 그냥 INSERT 는 같은 키에서 멈춘다 ==
  에러  INSERT INTO stock VALUES ('A-100', '볼펜', 3, NULL, '2026-10-05')
        -> IntegrityError: UNIQUE constraint failed: stock.sku

== 2. DO NOTHING — 있으면 넘어가고 없으면 넣는다 ==
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('A-100', '볼펜', 3, '2026-10-05') ON CONFLICT (sku) DO NOTHING
        -> 바뀐 행 0
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('C-300', '지우개', 7, '2026-10-05') ON CONFLICT (sku) DO NOTHING
        -> 바뀐 행 1

[2-A 결과]
  SELECT rowid, sku, qty, memo, updated_at FROM stock ORDER BY sku
  ('rowid', 'sku', 'qty', 'memo', 'updated_at')
  (1, 'A-100', 10, '창고 2층', '2026-10-01')
  (2, 'B-200', 5, None, '2026-10-01')
  (3, 'C-300', 7, None, '2026-10-05')

== 3. DO UPDATE — excluded 는 넣으려던 값, 컬럼 이름만 쓰면 기존 값 ==
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('A-100', '볼펜', 3, '2026-10-05') ON CONFLICT (sku) DO UPDATE SET qty = qty + excluded.qty, updated_at = excluded.updated_at
        -> 바뀐 행 1

[3-A A-100 은 10 + 3, 메모는 그대로]
  SELECT rowid, sku, qty, memo, updated_at FROM stock ORDER BY sku
  ('rowid', 'sku', 'qty', 'memo', 'updated_at')
  (1, 'A-100', 13, '창고 2층', '2026-10-05')
  (2, 'B-200', 5, None, '2026-10-01')
  (3, 'C-300', 7, None, '2026-10-05')

== 4. DO UPDATE ... WHERE — 조건이 거짓이면 아무것도 안 한다 ==
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('B-200', '공책', 0, '2026-09-30') ON CONFLICT (sku) DO UPDATE SET qty = excluded.qty, updated_at = excluded.updated_at WHERE excluded.updated_at > stock.updated_at
        -> 바뀐 행 0
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('B-200', '공책', 0, '2026-10-06') ON CONFLICT (sku) DO UPDATE SET qty = excluded.qty, updated_at = excluded.updated_at WHERE excluded.updated_at > stock.updated_at
        -> 바뀐 행 1

[4-A 오래된 값은 무시, 새 값만 반영]
  SELECT rowid, sku, qty, memo, updated_at FROM stock ORDER BY sku
  ('rowid', 'sku', 'qty', 'memo', 'updated_at')
  (1, 'A-100', 13, '창고 2층', '2026-10-05')
  (2, 'B-200', 0, None, '2026-10-06')
  (3, 'C-300', 7, None, '2026-10-05')

== 5. INSERT OR REPLACE 는 지우고 새로 넣는다 ==
  성공  INSERT OR REPLACE INTO stock (sku, name, qty, updated_at) VALUES ('A-100', '볼펜', 20, '2026-10-07')
        -> 바뀐 행 1

[5-A 메모가 사라지고 rowid 가 바뀐다]
  SELECT rowid, sku, qty, memo, updated_at FROM stock ORDER BY sku
  ('rowid', 'sku', 'qty', 'memo', 'updated_at')
  (4, 'A-100', 20, None, '2026-10-07')
  (2, 'B-200', 0, None, '2026-10-06')
  (3, 'C-300', 7, None, '2026-10-05')

== 6. 같은 문장 안에서 같은 키가 두 번 나오면 ==
  성공  INSERT INTO stock (sku, name, qty, updated_at) VALUES ('D-400', '자', 1, '2026-10-07'), ('D-400', '자', 2, '2026-10-07') ON CONFLICT (sku) DO UPDATE SET qty = qty + excluded.qty
        -> 바뀐 행 2

[6-A 두 번째 행이 첫 번째 행과 충돌한다]
  SELECT sku, qty FROM stock WHERE sku = 'D-400'
  ('sku', 'qty')
  ('D-400', 3)

== 7. 충돌 대상을 무엇으로 잡는가 ==
  성공  INSERT INTO member (id, email, nickname) VALUES (3, 'a@example.com', '도윤2') ON CONFLICT (email) DO UPDATE SET login_count = login_count + 1
        -> 바뀐 행 1
  에러  INSERT INTO member (id, email, nickname) VALUES (1, 'new@example.com', '새회원') ON CONFLICT (email) DO UPDATE SET login_count = login_count + 1
        -> IntegrityError: UNIQUE constraint failed: member.id
  에러  INSERT INTO member (id, email, nickname) VALUES (1, 'new@example.com', '새회원') ON CONFLICT (nickname) DO NOTHING
        -> OperationalError: ON CONFLICT clause does not match any PRIMARY KEY or UNIQUE constraint
  성공  INSERT INTO member (id, email, nickname) VALUES (1, 'new@example.com', '새회원') ON CONFLICT (email) DO UPDATE SET login_count = login_count + 1 ON CONFLICT (id) DO NOTHING
        -> 바뀐 행 0
  성공  INSERT INTO member (id, email, nickname) VALUES (2, 'x@example.com', '서준2') ON CONFLICT DO UPDATE SET login_count = login_count + 1
        -> 바뀐 행 1
  성공  INSERT INTO member (id, email, nickname) VALUES (9, 'b@example.com', '서준3') ON CONFLICT DO UPDATE SET login_count = login_count + 1
        -> 바뀐 행 1

[7-A 회원 표]
  SELECT id, email, nickname, login_count FROM member ORDER BY id
  ('id', 'email', 'nickname', 'login_count')
  (1, 'a@example.com', '도윤', 4)
  (2, 'b@example.com', '서준', 3)

== 8. INSERT ... SELECT 에 붙일 때 ==
  에러  INSERT INTO stock (sku, name, qty, updated_at) SELECT sku, name, qty, '2026-10-07' FROM incoming ON CONFLICT (sku) DO UPDATE SET qty = qty + excluded.qty
        -> OperationalError: near "DO": syntax error
  성공  INSERT INTO stock (sku, name, qty, updated_at) SELECT sku, name, qty, '2026-10-07' FROM incoming WHERE true ON CONFLICT (sku) DO UPDATE SET qty = qty + excluded.qty
        -> 바뀐 행 2

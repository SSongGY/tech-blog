# 예제 코드 — LEFT JOIN — 없는 쪽을 남기는 조인

메모리 SQLite에 고객 4명·주문 5건·배송 2건을 넣고, `LEFT JOIN`의 조건을 `ON`에 둘 때와 `WHERE`에
둘 때 결과가 어떻게 갈리는지, 짝이 없는 행을 찾는 질의가 어디서 틀리는지 확인한다.
외부 의존성 없이 파이썬 표준 라이브러리만 쓴다.

## 실행

```bash
python left_join_basics.py
```

## 바꿔볼 값

- `SALE_ORDERS`의 104번 상태를 `"완료"`로 바꾸면 이하윤이 2-A에도 나타난다.
  2-A와 2-C가 이하윤 한 명 차이로 갈리는 이유를 보는 자리다.
- `SALE_ORDERS`의 모든 `coupon_code`를 채우면 4-B가 4-A와 같은 답(최시우 1명)을 낸다.
  컬럼이 우연히 안 비어 있을 때만 맞는 질의라는 뜻이다.
- `SHIPMENTS`에 `(303, 102)`를 넣으면 6-B가 3행이 된다. 그래도 이하윤·최시우는 돌아오지 않는다.
- 7-A·7-B의 실행계획을 비교한다. `WHERE`에 조건을 둔 쪽은 `LEFT-JOIN` 표시가 사라지고
  조인 순서가 바뀐다.

스키마와 데이터 — 아래 질의는 전부 이 표를 대상으로 한다
================================================================
[employee]  2000행
  컬럼   | 타입    | 제약
  -------+---------+---------
  id     | INTEGER | PK
  emp_no | TEXT    | NOT NULL
  status | TEXT    | NOT NULL
  name   | TEXT    | NOT NULL

  id | emp_no | status | name
  ---+--------+--------+---------
   1 | E00001 | 재직   | 사원0001
   2 | E00002 | 재직   | 사원0002
   3 | E00003 | 재직   | 사원0003
   4 | E00004 | 재직   | 사원0004
   5 | E00005 | 재직   | 사원0005
   6 | E00006 | 재직   | 사원0006
   7 | E00007 | 재직   | 사원0007
   8 | E00008 | 재직   | 사원0008
   9 | E00009 | 재직   | 사원0009
  10 | E00010 | 재직   | 사원0010
  11 | E00011 | 재직   | 사원0011
  12 | E00012 | 재직   | 사원0012
  … 1988행 더 있음

[인덱스]
  이름           | 대상 표  | 정의
  ---------------+----------+------------------------------------------------
  idx_emp_emp_no | employee | CREATE INDEX idx_emp_emp_no ON employee(emp_no)
  idx_emp_status | employee | CREATE INDEX idx_emp_status ON employee(status)

================================================================
각 조건이 실제로 몇 행을 남기는가
================================================================
    status = '재직'          -> 1980행으로 좁혀진다
    emp_no = 'E01234'      ->    1행으로 좁혀진다

================================================================
통계 없음 — 같은 질의, 같은 데이터, 같은 두 인덱스
================================================================
  [A판] 인덱스 만든 순서: emp_no -> status
  QUERY PLAN
  `--SEARCH employee USING INDEX idx_emp_status (status=?)
  결과: [('사원1234',)]

  [B판] 인덱스 만든 순서: status -> emp_no
  QUERY PLAN
  `--SEARCH employee USING INDEX idx_emp_emp_no (emp_no=?)
  결과: [('사원1234',)]

================================================================
ANALYZE 실행 후 — 같은 질의, 같은 데이터, 같은 두 인덱스
================================================================
  [A판] 인덱스 만든 순서: emp_no -> status
  QUERY PLAN
  `--SEARCH employee USING INDEX idx_emp_emp_no (emp_no=?)
  결과: [('사원1234',)]
  sqlite_stat1:
    idx_emp_emp_no   2000 1

==============================================================
1. 별칭 없이 같은 표를 두 번 부르면 어느 쪽인지 가릴 수 없다
==============================================================
  에러 별칭 없음: ambiguous column name: name
  OK   별칭 e, m: 6행

==============================================================
2. 직원 옆에 상사 이름 붙이기 — JOIN 과 LEFT JOIN 의 차이
==============================================================
-- JOIN: 상사가 있는 직원만
  이부장    상사 김대표
  박팀장    상사 이부장
  최사원    상사 박팀장
  정사원    상사 박팀장
  한부장    상사 김대표
  오대리    상사 한부장
-- LEFT JOIN: 상사가 없는 대표까지
  김대표    상사 (없음)
  이부장    상사 김대표
  박팀장    상사 이부장
  최사원    상사 박팀장
  정사원    상사 박팀장
  한부장    상사 김대표
  오대리    상사 한부장

==============================================================
3. 상사보다 급여가 많은 직원 — 두 행의 값을 한 줄에서 비교한다
==============================================================
  정사원 520 > 박팀장 500

==============================================================
4. 같은 부서 직원끼리 짝짓기 — <> 와 < 는 행 수가 두 배 차이 난다
==============================================================
-- a.emp_id <> b.emp_id : 14행
  영업 한부장-오대리
  영업 오대리-한부장
-- a.emp_id < b.emp_id : 7행
  영업 한부장-오대리

==============================================================
5. 전날과 비교하기 — 자기 조인은 '전날', LAG 는 '이전 행'을 가져온다
==============================================================
-- 자기 조인: prev.sale_day = date(cur.sale_day, '-1 day')
  2026-03-01  100  전날 None       None
  2026-03-02  120  전날 2026-03-01  100
  2026-03-03   90  전날 2026-03-02  120
  2026-03-05  130  전날 None       None
  2026-03-06  130  전날 2026-03-05  130
-- LAG(): 정렬 순서에서 바로 앞 행
  2026-03-01  100  앞행 None       None
  2026-03-02  120  앞행 2026-03-01  100
  2026-03-03   90  앞행 2026-03-02  120
  2026-03-05  130  앞행 2026-03-03   90
  2026-03-06  130  앞행 2026-03-05  130

==============================================================
6. 조건을 어느 별칭에 거느냐로 결과가 갈린다
==============================================================
  에러 WHERE dept = '개발' (별칭 없음): ambiguous column name: dept
  WHERE e.dept = '개발' → 4행 (개발부 직원)
  WHERE m.dept = '개발' → 3행 (상사가 개발부)

==============================================================
7. 질의 계획 — 두 번째 employee 는 기본키로 찾아간다
==============================================================
QUERY PLAN
|--SCAN e
`--SEARCH m USING INTEGER PRIMARY KEY (rowid=?)
-- 짝짓기 조인: 부서에 인덱스가 없을 때
QUERY PLAN
|--SCAN a
`--SEARCH b USING AUTOMATIC COVERING INDEX (dept=?)
-- 부서에 인덱스를 만든 뒤
QUERY PLAN
|--SCAN a
`--SEARCH b USING INDEX ix_employee_dept (dept=? AND rowid>?)

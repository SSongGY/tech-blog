# 예제 코드 — 복합 기본키와 대리키 — 어느 쪽을 쓸까

같은 사실(학생·강좌·수강·출석)을 자연키 스키마와 대리키 스키마 두 벌로 만들어
크기·갱신 범위·조회 경로·키 재사용을 대조한다. 의존성은 없다.

## 실행

```bash
python key_design.py
```

`probe_natural.db`, `probe_surrogate.db` 두 파일을 만든다. 돌릴 때마다 지우고 새로
만들므로 남아 있어도 된다. 이름이 `probe` 로 시작해 저장소가 추적하지 않는다.

## 바꿔볼 값

| 상수 | 기본값 | 바꾸면 |
|---|---|---|
| `COURSE_COUNT` | 300 | 줄이면 강좌당 출석 행이 늘어 2절의 연쇄 갱신 범위가 커진다 |
| `MEETINGS_PER_ENROLLMENT` | 8 | 자식 표가 깊어질수록 자연키 복제 비용이 커진다 |
| `course_code()` | `CS-2026-0007` | 더 긴 자연키로 바꾸면 1절의 크기 차이가 그만큼 벌어진다 |

`enrollment_pairs()` 는 난수를 쓰지 않으므로 몇 번을 돌려도 같은 데이터가 나온다.

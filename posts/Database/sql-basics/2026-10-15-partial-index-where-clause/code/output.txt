2. 같은 부분 인덱스에 질의만 바꾼다 — 언제 안 쓰이는가
================================================================
인덱스: CREATE INDEX idx_pending ON order_tbl(ordered_at) WHERE status = 'pending'

조건에 리터럴 'pending' 을 그대로 쓴다  →  쓴다
  SELECT id FROM order_tbl WHERE status = 'pending' ORDER BY ordered_at
    SCAN order_tbl USING COVERING INDEX idx_pending

같은 조건을 바인딩 파라미터로 넘긴다  →  쓴다
  SELECT id FROM order_tbl WHERE status = ? ORDER BY ordered_at
    SCAN order_tbl USING COVERING INDEX idx_pending

AND 로 다른 조건이 더 붙는다  →  쓴다
  SELECT id FROM order_tbl WHERE status = 'pending' AND amount > 50000
    SCAN order_tbl USING INDEX idx_pending

OR 로 다른 상태를 함께 찾는다  →  안 쓴다
  SELECT id FROM order_tbl WHERE status = 'pending' OR status = 'done'
    SCAN order_tbl

IN 으로 하나만 적는다  →  안 쓴다
  SELECT id FROM order_tbl WHERE status IN ('pending')
    SCAN order_tbl

색인 밖의 상태를 찾는다  →  안 쓴다
  SELECT id FROM order_tbl WHERE status = 'done' ORDER BY ordered_at
    SCAN order_tbl
    USE TEMP B-TREE FOR ORDER BY

상태 조건이 아예 없다  →  안 쓴다
  SELECT id FROM order_tbl ORDER BY ordered_at
    SCAN order_tbl
    USE TEMP B-TREE FOR ORDER BY

CREATE UNIQUE INDEX idx_live_email ON member(email) WHERE deleted_at IS NULL

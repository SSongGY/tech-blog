-- 1. 오름차순 기본값 — NULL은 어디로 가는가
   ORDER BY bonus ASC
   김서연  개발   NULL
   정우성  영업   NULL
   최유진  영업    150
   강민수  개발    300
   박지훈  개발    300
   이하늘  영업    500

-- 2. 내림차순 기본값
   ORDER BY bonus DESC
   이하늘  영업    500
   강민수  개발    300
   박지훈  개발    300
   최유진  영업    150
   김서연  개발   NULL
   정우성  영업   NULL

-- 3. 오름차순인데 NULL을 뒤로
   ORDER BY bonus ASC NULLS LAST
   최유진  영업    150
   강민수  개발    300
   박지훈  개발    300
   이하늘  영업    500
   김서연  개발   NULL
   정우성  영업   NULL

-- 4. 내림차순인데 NULL을 앞으로
   ORDER BY bonus DESC NULLS FIRST
   김서연  개발   NULL
   정우성  영업   NULL
   이하늘  영업    500
   강민수  개발    300
   박지훈  개발    300
   최유진  영업    150

-- 5. 정렬 키 두 개 — 1순위 team, 2순위 bonus
   ORDER BY team ASC, bonus DESC
   강민수  개발    300
   박지훈  개발    300
   김서연  개발   NULL
   이하늘  영업    500
   최유진  영업    150
   정우성  영업   NULL

-- 6. 키마다 방향을 따로 준다
   ORDER BY team DESC, bonus ASC NULLS LAST
   최유진  영업    150
   이하늘  영업    500
   정우성  영업   NULL
   강민수  개발    300
   박지훈  개발    300
   김서연  개발   NULL

-- 7. 동점(bonus 300)을 가르는 3순위 키
   ORDER BY bonus DESC NULLS LAST, hired_on ASC
   이하늘  영업    500
   강민수  개발    300
   박지훈  개발    300
   최유진  영업    150
   김서연  개발   NULL
   정우성  영업   NULL

-- 8. 동점 행의 순서는 왜 믿으면 안 되는가
   인덱스 없음         결과: ['강민수', '박지훈']
   QUERY PLAN
   `--SCAN employee
   인덱스 생성 후       결과: ['박지훈', '강민수']
   QUERY PLAN
   `--SEARCH employee USING COVERING INDEX idx_bonus_name (bonus=?)

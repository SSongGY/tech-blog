-- 1. 인덱스가 없을 때 — 고객 777의 주문
   QUERY PLAN
   `--SCAN orders
   결과 10행 · VM 명령 60,038개

-- 2. CREATE INDEX 로 만든 뒤
   CREATE INDEX ix_orders_customer_id ON orders (customer_id)
   성공
   QUERY PLAN
   `--SEARCH orders USING INDEX ix_orders_customer_id (customer_id=?)
   결과 10행 · VM 명령 71개

-- 3. 만든 인덱스 확인과 같은 이름으로 한 번 더
   SELECT name, "unique", origin FROM pragma_index_list('orders')
   ix_orders_customer_id | 0 | c
   SELECT seqno, name FROM pragma_index_info('ix_orders_customer_id')
   0 | customer_id
   CREATE INDEX ix_orders_customer_id ON orders (customer_id)
   에러: index ix_orders_customer_id already exists
   CREATE INDEX IF NOT EXISTS ix_orders_customer_id ON orders (customer_id)
   성공

-- 4. UNIQUE INDEX — 이미 겹치는 값이 있으면 만들어지지 않는다
   CREATE UNIQUE INDEX ux_orders_customer_id ON orders (customer_id)
   에러: UNIQUE constraint failed: orders.customer_id
   SELECT COUNT(*) FROM pragma_index_list('orders')
   1

-- 5. 값이 3가지뿐인 컬럼 — status
   SELECT status, COUNT(*) FROM orders GROUP BY status
   cancelled | 6603
   paid | 6586
   shipped | 6811
   CREATE INDEX ix_orders_status ON orders (status)
   성공
   QUERY PLAN
   `--SEARCH orders USING INDEX ix_orders_status (status=?)
   인덱스 사용 · 결과 (6586, 165356700) · VM 명령 39,530개 · 0.67 ms
   NOT INDEXED · 결과 (6586, 165356700) · VM 명령 79,771개 · 0.72 ms

-- 6. ANALYZE 로 통계를 만든 뒤
   ANALYZE
   성공
   SELECT idx, stat FROM sqlite_stat1 ORDER BY idx
   ix_orders_customer_id | 20000 10
   ix_orders_status | 20000 6667
   QUERY PLAN
   `--SEARCH orders USING INDEX ix_orders_status (status=?)
   QUERY PLAN
   `--SEARCH orders USING INDEX ix_orders_customer_id (customer_id=?)

-- 7. DROP INDEX
   DROP INDEX ix_orders_customer_id
   성공
   DROP INDEX ix_orders_customer_id
   에러: no such index: ix_orders_customer_id
   DROP INDEX IF EXISTS ix_orders_customer_id
   성공
   - 지운 뒤 같은 연결에서 1번과 같은 EXPLAIN QUERY PLAN 을 다시 돌리면
   QUERY PLAN
   `--SEARCH orders USING INDEX ix_orders_customer_id (customer_id=?)
   - 문장 캐시를 끈 연결(cached_statements=0)에서 만들고 지운 뒤 돌리면
   QUERY PLAN
   `--SCAN orders

-- 8. 저장 공간 — 인덱스를 하나씩 더할 때 늘어나는 페이지

   표만: 160 페이지

   + ix_orders_status             283 페이지 (+73)

-- 9. 쓰기 비용 — 같은 20,000행을 인덱스 수만 바꿔 INSERT
   인덱스 0개: VM 명령   400,013개 ·  160 페이지 ·   10.8 ms
   인덱스 1개: VM 명령   520,013개 ·  214 페이지 ·   18.5 ms
   인덱스 3개: VM 명령   720,013개 ·  399 페이지 ·   35.8 ms
   0개로 넣고 3개를 나중에: VM 명령   940,175개 ·  372 페이지 ·   22.8 ms
   - INSERT 한 행을 컴파일한 프로그램에서 Insert(표)·IdxInsert(인덱스) 명령
     인덱스 0개: Insert 1개 · IdxInsert 0개
     인덱스 1개: Insert 1개 · IdxInsert 1개
     인덱스 3개: Insert 1개 · IdxInsert 3개
   - 이미 행이 있는 표에 CREATE INDEX 를 컴파일한 프로그램의 정렬 명령
     SorterOpen · SorterInsert · SorterSort · SorterData · SorterNext

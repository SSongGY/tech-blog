# 예제 코드 — 실행계획의 비용(cost)은 무엇을 세는 숫자인가

메모리 DB에 주문 표 `orders` 10만 행과 인덱스 두 개(`status`, `customer_id`)를 만들고,
통계(`sqlite_stat1`)와 실제 데이터가 어긋날 때 옵티마이저가 무엇을 고르는지 본다.
파이썬 표준 라이브러리만 쓴다. 난수는 시드를 고정했다.

| 장 | 무엇을 보는가 |
|---|---|
| 1 | `ANALYZE` 직후 — 선택도가 높은 `status` 인덱스를 고르는 것과, 고르지 않은 쪽의 실제 일 |
| 2 | 주문 99%를 `'DONE'`으로 바꾸고 통계는 그대로 둘 때 — 낡은 통계로 고른 계획의 실제 일 |
| 3 | `ANALYZE`를 다시 돌린 뒤 계획이 바뀌는 것, 같은 통계에서 드문 값을 찾을 때, STAT4 컴파일 여부 |
| 4 | `sqlite_stat1`을 손으로 바꾸면 데이터는 그대로인데 계획이 바뀌는 것 |

일의 양은 질의 하나가 실행한 VDBE(가상 머신) 명령 수로 센다.
`set_progress_handler`를 명령 1개마다 불리게 건다. 시간은 7회 중앙값이다.

## 실행

```bash
python stale_statistics.py
```

## 바꿔볼 값

- `ROW_COUNT`를 1만·100만으로 바꾸면 2장의 명령 수 차이가 행 수에 비례해 벌어지는지 본다.
- 2장의 `UPDATE` 조건을 `order_id % 2 <> 0`(50%)으로 바꾸면 낡은 통계의 손해가 얼마나 줄어드는지 본다.
- 4장의 `'100000 100000'`을 `'100000 10'`으로 바꾸면 옵티마이저가 다시 어느 쪽을 고르는지 본다.

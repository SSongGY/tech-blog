# Jump 일관 해시

Lamping·Veach(2014)의 jump consistent hash 를 파이썬으로 옮기고, 가상 노드를 둔 링 해시와
옮겨 가는 키·버킷 편차·시간·메모리를 비교한다. 표준 라이브러리만 쓴다.

## 실행

```bash
python jump_hash.py
```

키 100만 개로 링을 여러 번 만들어 1~2분 걸린다.

## 바꿔 볼 값

- `KEY_COUNT` 를 줄이면 [3]의 jump 편차가 키 수에 따라 커진다. 편차가 알고리즘이 아니라 표본에서 온다는 것을 본다
- `SEED` 를 바꿔도 [2]의 옮긴 비율은 이론값 근처에 머문다
- [4]의 `points` 에 1000 을 넣으면 링에서 키를 내주는 버킷 수가 늘어난다(시간이 더 걸린다)

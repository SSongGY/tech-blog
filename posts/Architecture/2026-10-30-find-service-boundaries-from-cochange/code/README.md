# 커밋 이력에서 모듈 경계 찾기 — 예제

임시 폴더에 진짜 git 저장소를 만들어 정해 둔 26개 커밋을 쌓고,
`git log --name-only` 를 읽어 **함께 바뀌는 파일**을 묶는다.
동시 변경 횟수만 쓸 때와 자카드 계수를 쓸 때 묶음이 어떻게 갈리는지 비교한다.

의존성은 없다. 파이썬 표준 라이브러리와 PATH 의 `git` 만 쓴다.
임시 저장소는 끝나면 지운다.

## 실행

```bash
python cochange.py
```

## 바꿔볼 값

| 자리 | 바꾸면 |
|---|---|
| `HISTORY` | 커밋 이력 자체다. 파일 묶음을 바꾸면 추정되는 경계가 달라진다 |
| 3절의 `(3, 4)` | 동시 변경 횟수 기준. 올릴수록 묶음이 잘게 쪼개진다 |
| 4절의 `(0.3, 0.4)` | 자카드 기준. 0.5 를 넘기면 대부분 혼자 남는다 |
| `common/config.py` 를 `HISTORY` 에서 빼기 | 모든 묶음을 잇던 파일이 사라지면 동시 변경 횟수만으로도 갈린다 |

## 파일

- `cochange.py` — 저장소 생성부터 군집화까지 전부 하는 스크립트
- `output.txt` — `blog.py run-example` 이 남긴 실행 기록

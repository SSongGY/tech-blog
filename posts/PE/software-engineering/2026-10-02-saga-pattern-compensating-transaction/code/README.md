# 예제 코드 — 사가와 보상 트랜잭션

주문·결제·재고 서비스를 서로 다른 SQLite 메모리 DB 세 개로 두고, 오케스트레이터가
지역 트랜잭션 T1·T2·T3을 차례로 커밋한다. T3이 실패하면 C2·C1을 거꾸로 실행한다.
외부 의존성 없이 파이썬 표준 라이브러리만 쓴다.

## 실행

```bash
python saga_demo.py
```

## 바꿔볼 값

- `main()`의 A-2에서 `stock_qty=0`을 `1`로 바꾸면 보상이 일어나지 않는다.
- `deposit()`의 5000을 바꿔도 C-1은 늘 기대 잔액과 같고, C-2는 늘 입금액만큼 모자란다.
- `c1()`을 `DELETE FROM orders`로 바꾸면 B에서 끼어든 조회가 본 주문 1번이 사가가 끝난 뒤 흔적 없이 사라진다.

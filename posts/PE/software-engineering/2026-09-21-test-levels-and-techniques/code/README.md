# 문장 커버리지와 분기 커버리지 계산

ISTQB CTFL v4.0.1 §4.3.2의 "분기 커버리지가 문장 커버리지를 포함한다"를
실행 추적으로 직접 계산해 확인한다.

## 실행

```bash
python coverage_subsumption.py
```

의존성 없음. `sys.settrace`와 표준 라이브러리만 쓴다.
확인 환경: Python 3.13.5.

## 측정 방식

- **문장 커버리지** — `sys.settrace`의 `line` 이벤트로 실제 실행된 줄을 모아
  실행문 6줄(`STATEMENT_LINES`) 중 몇 줄을 밟았는지 센다.
- **분기 커버리지** — 판단문 줄(`DECISION_LINES`) 다음에 기록된 줄이 바로 아래 줄이면
  참 분기, 건너뛰었으면 거짓 분기로 센다. 손으로 표시하지 않고 추적 기록에서 끌어낸다.
  판단문 2개 × 참/거짓 = 전체 4개 분기.

## 바꿔 볼 값

- `suites`의 입력 조합 — `[(5, True)]` 한 건만 주면 `fee = fee + 2000` 줄이
  실행되지 않아 문장 커버리지도 100%에서 내려간다.
- `SOURCE`의 함수 — `if`에 `else`를 붙이면 문장 커버리지 100%를 달성하려면
  양쪽 분기를 모두 밟아야 하므로 두 수치가 같이 올라간다. 이것이 `else` 없는 `if`가
  커버리지 수치를 낙관적으로 만드는 이유다.
- `DECISION_LINES`와 `STATEMENT_LINES` — `SOURCE`를 고치면 줄 번호도 함께 맞춰야 한다.

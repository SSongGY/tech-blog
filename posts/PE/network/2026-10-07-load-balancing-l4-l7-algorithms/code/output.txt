== 1. 라운드 로빈 vs 가중 라운드 로빈 — 요청 600건
   라운드 로빈 (가중치 없음)
     web-a       200건   33.3%
     web-b       200건   33.3%
     web-c       200건   33.3%
   가중 라운드 로빈 (web-a 3 · web-b 2 · web-c 1)
     web-a       300건   50.0%

     web-c       100건   16.7%

== 2. 서버 한 대가 느릴 때 — 라운드 로빈 vs 최소 연결, 요청 3,000건
   짧은 요청(2틱) 2090건 · 긴 요청(40틱) 910건 · web-c 는 3배 느림
   round_robin  받은 요청: web-a 1000, web-b 1000, web-c 1000 / 최대 동시 접속: web-a 9, web-b 10, web-c 20
   least_conn   받은 요청: web-a 1292, web-b 1257, web-c 451 / 최대 동시 접속: web-a 9, web-b 9, web-c 9

== 3. 서버 4대 → 5대로 늘릴 때 자리를 옮기는 키의 비율 — 키 20,000개
   hash mod N          :  80.2% 이동  (이론값 1 - 1/5 = 80.0%: h mod 4 == h mod 5 인 키만 남는다)
   링 일관된 해시(160점) :  19.3% 이동  (이상적으로는 새 서버 몫 1/5 = 20.0% 만 옮긴다)
        링 일관된 해시 — 5대일 때 키 분포
     app-1      4574건   22.9%
     app-2      3748건   18.7%
     app-3      3718건   18.6%
     app-4      4092건   20.5%
     app-5      3868건   19.3%
   Maglev 해시(M=65537) :  19.6% 이동  (조회표 칸 20.1% 가 바뀜)
     Maglev 조회표 — 서버별 칸 수: app-1 13108, app-2 13108, app-3 13107, app-4 13107, app-5 13107  (최대-최소 1칸)

== 4. 세션 고정 — 출발지 IP 해시의 치우침, 세션 2,000개
   NAT 뒤 세션 602건 / 전체 2000건
   라운드 로빈으로 세션을 나누고 쿠키로 고정했을 때
     app-1       500건   25.0%
     app-2       500건   25.0%
     app-3       500건   25.0%
     app-4       500건   25.0%
   출발지 IP 해시로 고정했을 때
     app-1       993건   49.6%
     app-2       232건   11.6%
     app-3       362건   18.1%
     app-4       413건   20.6%
   -> IP 해시에서 가장 바쁜 서버 app-1 가 평균의 1.99배를 받는다
   -> app-1 가 내려가면 거기 고정돼 있던 세션 993건(49.6%)의 서버 측 상태가 사라진다. 세션 저장소를 밖에 두면 0건

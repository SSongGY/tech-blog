# 예제 코드 — PQ·WRR·DRR·WFQ의 바이트 몫

같은 백로그를 네 스케줄러에 넣고 링크가 일정 바이트를 보낼 때까지 흐름별로 몇 바이트를
보냈는지 센다. DRR은 적자 카운터가 라운드마다 어떻게 바뀌는지도 찍는다.
외부 의존성 없이 파이썬 표준 라이브러리만 쓴다.

## 실행

```bash
python scheduling_compare.py
```

## 모델

- **모든 흐름이 시각 0부터 계속 백로그**다. 이 조건에서 WFQ의 가상 시간은 전송 순서를
  바꾸지 않으므로 태그를 `F = F이전 + L/φ` 로만 계산했다. 도착이 흩어진 경우의 WFQ는
  기출 답안 예제(`posts/PE/exam/2026-10-01-fifo-vs-weighted-fair-queuing/code/`)가 다룬다.
- **DRR**은 Shreedhar·Varghese 논문 Figure 4의 의사코드를 그대로 옮겼다.
- **WRR**은 라운드마다 흐름별로 가중치만큼 **패킷 수**를 보낸다(ATM 셀처럼 길이가 고정일 때의 설계).
- 시간은 모델에 없다. 링크가 보낸 누적 바이트로 구간을 끊는다.

## 바꿔볼 값

- 시나리오 1에서 B의 패킷을 1500B로 바꾸면 WRR도 50:50이 된다. WRR의 불공정은 길이 차이에서만 생긴다.
- 시나리오 3의 Quantum을 1200 이상으로 올리면 Q3가 첫 라운드에 나간다.

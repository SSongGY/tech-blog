== 2. 스트림 ID 하위 2비트 — RFC 9000 §2.1 Table 1
   ID  0 (하위 2비트 0x00) : 클라이언트 시작 · 양방향
   ID  1 (하위 2비트 0x01) : 서버 시작 · 양방향
   ID  2 (하위 2비트 0x02) : 클라이언트 시작 · 단방향
   ID  3 (하위 2비트 0x03) : 서버 시작 · 단방향
   ID  4 (하위 2비트 0x00) : 클라이언트 시작 · 양방향
   ID  5 (하위 2비트 0x01) : 서버 시작 · 양방향
   ID  6 (하위 2비트 0x02) : 클라이언트 시작 · 단방향
   ID  7 (하위 2비트 0x03) : 서버 시작 · 단방향
   ID  8 (하위 2비트 0x00) : 클라이언트 시작 · 양방향
   ID  9 (하위 2비트 0x01) : 서버 시작 · 양방향
   ID 10 (하위 2비트 0x02) : 클라이언트 시작 · 단방향
   ID 11 (하위 2비트 0x03) : 서버 시작 · 단방향
   HTTP/3 요청 스트림(클라이언트 양방향)은 0, 4, 8, … / 제어 스트림은 단방향 2, 3, 6, 7, … 중 하나

== 3. 머리 막힘 모형 — 스트림 A·B·C 가 패킷 6개에 번갈아 실렸고 2번이 사라졌다
   전송 순서: 1:A 2:B 3:C 4:A 5:B 6:C
   TCP 위 HTTP/2 — 재전송을 기다리는 스트림: ['A', 'B', 'C']  (3개)
   QUIC 위 HTTP/3 — 재전송을 기다리는 스트림: ['B']  (1개)

== 4. 첫 요청을 보내기까지의 왕복 수 × RTT
   TCP 3-way 1 RTT(RFC 9293 §3.5) + TLS 1.3 1 RTT(RFC 8446 §2) = 2 RTT
   QUIC 1 RTT(RFC 9001 §4.1 — TLS 1.3 핸드셰이크를 전송 핸드셰이크와 합침), 재개 시 0-RTT
   RTT(ms) | TCP+TLS 1.3 | QUIC 첫 연결 | QUIC 0-RTT 재개

[1] 순서보존 암호 — 비교는 되지만 순서가 그대로 새어 나간다
    평문 공간 100개(나이 0~99) -> 암호문 공간 65536개
    앞 5개 대응: 0->253, 1->1566, 2->3950, 3->6830, 4->7087
    서버가 키 없이 '나이 >= 60' 범위 질의 수행: 390건 (평문으로 센 값 390건)
    조밀한 열(1,000행, 서로 다른 값 100개) 정렬 공격: 1000/1000행 복원
    희소한 열(30행, 서로 다른 값 25개) 정렬 공격: 0/30행 복원
    같은 30행을 '암호문/65536*100'으로 어림: 평균 오차 1.8세, 최대 3세, 오차 10세 이내 30/30행
    키를 바꾸면 나이 40의 암호문: 26862 -> 18140 (값은 달라도 순서는 같다)

[2] 형태보존 암호 — 자리 수와 문자 종류가 그대로라 스키마를 안 바꾼다
    9410123412341234 -> 5064058452285246  (길이 16, 숫자만: True, 복호 일치: True)
    9410987698769876 -> 1347577883545281  (길이 16, 숫자만: True, 복호 일치: True)
    9410123412341234 -> 5064058452285246  (길이 16, 숫자만: True, 복호 일치: True)
    같은 카드번호의 암호문이 같은가: True -> 같은 값끼리 묶이고 빈도가 보인다
    VARCHAR(16) 컬럼에 그대로 들어가는가: True
    두 자리 값(00~99)을 전부 암호화한 서로 다른 암호문 수: 100개 -> 정의역이 작으면 100개 대응표로 전부 풀린다

[3] 동형 암호(Paillier) — 암호문 상태로 더하지만 비교·정렬은 못 한다
    급여 5건을 암호문끼리 곱함 -> 복호: 1905 (평문 합계 1905)
    '가'의 암호문을 3제곱 -> 복호: 960 (320 x 3 = 960)
    같은 320을 두 번 암호화한 암호문이 같은가: False -> 같은 값끼리 묶이지 않는다
    암호문 크기 비교 E(505) > E(320): False -> 암호문의 대소는 평문의 대소와 무관하다
    평문 9비트 -> 암호문 약 184비트 (n² = 184비트)

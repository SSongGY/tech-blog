# 예제 코드 — 스키마를 언제 강제하는가

주문 이벤트 6건(쉼표 섞인 금액 1건, 금액 없는 1건, 원천에 없던 필드가 붙은 1건 포함)을
웨어하우스·레이크·레이크하우스 세 방식으로 저장하고 읽어 결과를 나란히 찍는다.
실제 제품이 아니라 개념을 파이썬 표준 라이브러리로 옮긴 모형이다.

- 웨어하우스: SQLite `STRICT` 표에 적재 — 적재 시점에 거부
- 레이크: JSON 파일을 그대로 저장 — 읽는 팀마다 해석이 다르다
- 레이크하우스: 데이터 파일 + 번호 붙은 로그 파일(`_log/00000.json` …). 로그가 스키마와
  "이 버전에 속한 파일"을 들고, 쓸 때 스키마로 검사하고 읽을 때 로그로 파일 목록을 정한다

## 실행

```bash
python schema_timing.py
```

## 바꿔볼 값

- `EVENTS` 2번의 `"15,000"`을 `15000`으로 고치면 세 방식의 합계가 어떻게 바뀌는지 본다.
- `lenient_reader`가 금액이 없을 때 0 대신 `None`을 돌려주게 바꾸면 팀 B의 건수가 바뀐다.
- `LakehouseTable.write`의 검사 조건에서 `set(e) == set(schema)`를 빼면 coupon 필드가 붙은 5번이 들어간다.

# 예제 코드 — 근사 탐색이 필요한 이유와 HNSW 계층 구조 검산

본문이 주장하는 네 가지를 직접 계산해 확인한다. HNSW 색인 자체를 구현하지는 않는다.
색인 구현은 공개 라이브러리가 하는 일이고, 여기서 확인하려는 것은 **그 구현이 서 있는
전제가 실제로 성립하는가**다.

- 차원이 오르면 최근접점과 최원점의 거리가 붙는다 (Beyer 외, ICDT 1999)
- 계층 배정식 `l = ⌊-ln(unif(0,1))·mL⌋` 가 만드는 계층별 원소 수
- `mL = 1/ln(M)` 이 skip list 의 `p = 1/M` 에 대응한다는 논문 4.1절의 진술
- 원소당 평균 연결 수 `Mmax0 + mL·Mmax` (논문 4.2.3절)

## 요구 사항

- Python 3.9 이상 (표준 라이브러리만 사용, 추가 설치 없음)

## 실행

```bash
python ann_probe.py
```

`[1]`은 순수 파이썬으로 2,500만 번의 좌표 연산을 돌리므로 1분 안팎이 걸린다.

## 출력 구성

| 섹션 | 내용 |
|---|---|
| `[1]` | `d`를 2에서 512까지 올리며 `(Dmax−Dmin)/Dmin` 중앙값을 잰다 |
| `[2]` | 원소 100만 개를 논문의 계층 배정식으로 흩뿌려 계층별 원소 수를 센다 |
| `[3]` | `M`을 5·16·48로 바꿔 `exp(−1/mL)`·`1/M`·실측 계층비를 나란히 비교 |
| `[4]` | 같은 `M` 값에서 원소당 연결 수와 1억 원소 기준 그래프 메모리 |

## 계산 조건

- 난수 씨앗은 `SEED = 20260922` 고정. 몇 번을 돌려도 같은 값이 나온다
- `[1]`은 `[0,1]^d` 균등난수 1,000점에 질의 25개. 질의가 우연히 한 점 위에 떨어지면
  분모가 0에 가까워지므로 평균이 아니라 **중앙값**을 쓴다
- `[2]`~`[4]`는 원소 1,000,000개, `Mmax0 = 2M`, `Mmax = M`, 링크 4바이트로 둔다

## 값을 바꿔가며 확인할 것

- `POINTS`를 10,000으로 올려도 `[1]`의 흐름은 같다. 점을 늘리면 최근접이 가까워져
  비율이 조금 커지지만, 차원이 오를 때 무너지는 속도는 바뀌지 않는다
- `M_DEFAULT`를 5로 낮추면 `[2]`의 최상위 계층이 올라간다. `mL`이 커져 계층이
  더 얇게 쪼개지기 때문이다
- `M_VALUES`에 100처럼 논문 권장 범위(5~48) 밖의 값을 넣어 보면 `[4]`의 메모리가
  왜 `M`에 비례해 늘어난다고 하는지 눈에 보인다

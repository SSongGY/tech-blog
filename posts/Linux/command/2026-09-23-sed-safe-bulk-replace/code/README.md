# 예제 코드 — sed 일괄 치환을 안전하게 쓰는 법

외부 의존성 없다. 스크립트가 `sed_work/` 폴더를 만들어 설정 파일 세 개(`app.conf`,
`batch.conf`, CRLF 줄끝의 `crlf.conf`)를 쓰고, 미리보기·백업·`-i`·주소·플래그·옵션을
하나씩 돌린 뒤 폴더째 지운다.

## 실행

```bash
bash sed_safe_replace.sh
```

확인 환경: GNU sed 4.9 / bash 5.3.9 (Git Bash on Windows 11).

## 각 장이 보는 것

| 장 | 확인하는 것 |
|---|---|
| 2~4 | 점(`.`)이 아무 글자와 맞고, 경계가 없으면 `10.0.0.12`·`10.0.0.100`까지 바뀐다는 것 |
| 5 | `diff -u`로 파일 전체 변경을 미리 보는 것 |
| 6 | 치환이 0건이어도 종료 코드가 0이라는 것 |
| 7~8 | `-i.bak`, `-i'orig_*'`로 백업을 남기는 것 |
| 9 | `-i`가 새 파일을 만들어 하드 링크가 끊긴다는 것 |
| 10 | 여러 파일에서 `$`·`1` 주소가 `-s` 유무로 갈리는 것 |
| 11~13 | BRE/ERE, 구분자 바꾸기, `-e`·`-f` |
| 14~16 | 주소 형식, `s` 플래그, 줄 단위 명령 |
| 17~22 | `-z`, `-b`, `-l`, `--sandbox`, `--posix`, `--debug` |
| 23 | `-i`와 접미사 사이에 공백을 넣으면 접미사를 스크립트로 읽는다는 것 |
| 24 | 원본에 덮어쓰면 하드 링크가 유지된다는 것 |
| 25 | `-i` 없이 여러 파일에 `1i`를 쓰면 첫 파일에만 들어간다는 것 |

## 바꿔 볼 값

- `app.conf`의 `db.replica=10.0.0.12`를 `10.0.0.1`로 바꾸면 4장 두 번째 명령이 두 줄을 바꾼다.
  경계를 `=...$`로 건 치환은 "그 값 전체"만 바꾼다는 뜻이다.
- 9장의 `sed -i`를 `sed -i.bak`으로 바꿔도 하드 링크는 끊긴다. 백업 여부와 무관하게
  `-i`가 새 파일을 만들기 때문이다.
- 18장의 `-b`를 빼면 Git Bash의 sed가 줄끝 `\r`을 떼고 읽어 `=20$`가 맞는다.
  리눅스의 GNU sed에는 이 처리가 없으므로 `-b`를 붙인 쪽이 서버에서 보게 될 결과다.

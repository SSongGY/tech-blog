# 예제 코드 — grep으로 로그에서 원하는 줄만 뽑기

외부 의존성 없다. 스크립트가 12줄짜리 샘플 로그(`app.log`)를 직접 만들고,
문맥 옵션(`-A`/`-B`/`-C`)과 정규식 엔진 세 가지(BRE·ERE·PCRE)가 같은 패턴을
어떻게 다르게 읽는지를 한 파일 위에서 비교한 뒤 로그를 지운다.

## 실행

```bash
bash grep_context.sh
```

확인 환경: GNU grep 3.0 / bash 5.3.9 (Git Bash on Windows 11).
grep 3.7 이상에서는 `-E`에 쓴 불필요한 역슬래시에 경고가 붙는 경우가 있어
7장의 출력에 경고 한 줄이 더 붙을 수 있다. 건수는 같다.

## 각 장이 보는 것

| 장 | 확인하는 것 |
|---|---|
| 1~2 | 걸린 줄만 나오는 기본 동작과 `-C`로 앞뒤를 같이 보는 것 |
| 3 | `-A`(뒤)와 `-B`(앞)의 방향 |
| 4 | `-n` 줄 번호, `-c` 건수, `-i` 대소문자 무시로 건수가 늘어나는 것 |
| 5 | `.`이 임의의 한 글자라서 `5.0`이 `5002`에 걸리는 것과 `-F`의 차이 |
| 6 | `-w`가 요구하는 단어 경계 |
| 7 | 같은 `\d`를 BRE·ERE는 못 읽고 PCRE만 읽는 것 |
| 8 | "A는 있고 B는 없는 줄"을 `-P`의 전방탐색으로 한 번에 거르는 것 |
| 9 | `-o`로 매칭된 부분만 뽑아 집계에 넘기는 것 |
| 10 | `-c`가 세는 것이 줄 수지 매칭 수가 아니라는 것 |
| 11 | 못 찾았을 때의 종료 코드 1 |

## 바꿔 볼 값

- `make_log`의 로그 내용 — `ERROR` 줄의 위치를 바꾸면 `-C`가 묶는 블록 수가 달라진다.
  블록이 둘 이상이면 사이에 `--` 구분선이 붙는다.
- 5장의 `5.0` — `-F`를 붙이고 떼며 건수를 비교한다. 로그에 실제로 `5.0`이라는
  글자가 없으므로 `-F`는 0을 돌려준다.
- 7장의 `\d`를 `[0-9]`로 바꾸면 네 줄의 건수가 전부 같아진다.
- 8장의 `(?!.*timeout)`을 `(?=.*timeout)`으로 뒤집으면 반대쪽 줄이 나온다.
